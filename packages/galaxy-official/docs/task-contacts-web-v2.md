# Task 联系与房间网页衔接

关联 M26 RR-04/05；复用 M04、M11、M12 现有业务服务，无新增 API、表或迁移。

## 当前流程

`TaskPublishWorkspace` 的成功回执仍导航到实际 Task ID。`TaskCollaboration` 的联系人区域在本人首次进入 `suggestions.state=not-requested` 的任务时发起一次前台授权查询，不等待查询才发布任务。工作事实按原文关键词、可选能力字段筛选；功能意愿查询需要用户给出功能标签，能力字段可作为初始标签。没有功能标签不擅自推导语义标签。各来源保留独立游标和失败状态，空页及没有履历都不推断没有能力。

`TaskContactWorkspace(section='contacts')` 显示两种真实来源：工作事实的明确 Attempt／Intervention／Verification／Participation 作者，以及本人明确表达交流意愿的 Project／Module／Recruitment 作者。任务请求者身份本身不被当作做过相关工作的证明。清单保留来源精确投影摘要、版本及当前可读原始结构；用户填写本次帮助、选择依据和未决条件。保存建议前由 `/v2/search/reference` 重新核对原版本仍可读。保存的建议是私有选择记录，后续读取明确标成历史选择，不宣称来源或意愿持续有效。实际申请与回应由原 Task 服务独立显示。

单选或多选邀请先把批次、逐人稳定事件 ID、内容、期限存到本人端点命名空间。用户一次确认后逐项提交，每项在发出前固定完整 strict Task envelope 与 SHA-256。任务版本从上一个确定操作之后读取；已经尝试过的事件绝不重新编号或改版本。丢回执后先查询原 `/v2/tasks/receipt`，已接受者不重发、不重新签 Consent。无结果的原操作复用 runtime 原签名恢复。完全未发送的对象可以独立取消。

`section='rooms'` 从真实愿意了解的邀请回应、待审申请及当前参与者中选择分别交流或共同房间。创建只加入创建者，房间关联 Task 不能授予 Task、Context 或报价权限。每次房间创建和共同决定都有稳定 ID；原 create ACK 丢失时仅重试相同对象和载荷。

共同房间沿现有成员版本治理，不能先自动把所有人加入。先被邀请者明确回应以后，网页列出现有成员，未发送的下一人按当前成员重新预览。既有成员需要共同决定时，使用房间里的原投票流程，目标方随后自行接受。没有将这种治理约束写成固定先私聊后拉群；分别交流仍是同级可选路径。已婉拒的提议不自动追发。旧提议因成员变化失效后如用户重新提出，保留原提议历史，新提议仍受现有邀请额度及未回应冷却。

## 权限与失败

- Task→Room 按本人当前成员列表每页 50 个扫描，显示已检查数量及是否仍有下一页；不增加按 Task 绕过房间 ACL 的查询。
- Room→Task 对每个 `taskRefs` 重新请求当前 Task。不可读时仅显示不可用状态，不使用旧任务标题或正文。房间读取失败清空其旧成员、正文及关联任务投影。
- 关闭页面不会变成退出房间或取消实际邀请。完全未发送的房间预览可以明确取消；未知创建只能先恢复原 ID，不能假定不存在再创建第二个。
- 用户 Agent／用户自己解释、筛选和组织沟通，银河没有新增模型推理或后台语义匹配。
- 用户本人草稿和批次在浏览器本机存储，服务端写入仍经过原权限、配额、共同治理及源许可规则。

Task 的共用恢复入口同时提供“停止本机重试”：先核对原操作，已经接受就按完成处理；不存在、冲突或网络未知时，可明确停止本机队列。原 ID／精确 hash／动作／Consent ID／最小回执先存到仅查询的本人记录，然后清发送队列，档案没有原签名正文。未来在途操作仍可能完成，必须查询原回执；不以停止声称服务端已经撤回。队列写入和清空必须匹配原事件及 hash，晚到原请求不能恢复自己或覆盖后来的新队列。相同已停止 ID 禁止再发，申请、邀请、参与和请求者反馈共用，发布草稿继续保留。

## 挂点与验证

新增网页 `task-contact-client.mjs`、`task-contact-workspace.tsx`。`TaskCollaboration` 分别嵌入联系和房间区域；保留原申请、报价、资格、范围、交付、争议及单 ID 高级入口。`runtime.taskEvent`、`chat-client.create/propose` 仅增加接受原 strict schema 校验过的调用者稳定 ID；未提供时保持原随机生成行为。

`chat-workspace.tsx` 同时接入房间举报入口、当前 TaskRefs 往返，以及其他切片交付的 `AgentParticipants`；每人参与卡片接入 `RequesterFeedback`，这两者业务验证归各自切片。

关键测试：`node --test test/task-contacts-web-v2.test.mjs` 使用真实 BrowserRuntime、签名、HTTP、独立本地 OIDC 及数据库，三个合成账户；覆盖真实声明意愿的新人查询、精确来源建议私存、原邀请 ACK 丢失与重建客户端、逐人邀请、原房间 ACK 丢失、当前成员批准后目标方加入、Task 参与不被自动确认、匿名无私有联系人，以及永久版本冲突后明确停止→新操作执行→旧回执继续查询。浏览器本机存储使用显式内存替身，不宣称 IndexedDB 或人工界面已验收。此轮不需要重复底层无改动的 PostgreSQL／Prosody 验证。
