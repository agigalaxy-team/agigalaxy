# 查询与原聊天帮助

保留原工作目的、当前观察、已尝试的策略和不可外发约束。需要建议介入时，用几句说明已知什么、缺什么，以及外部资料可能改变哪一步；不用冗长自评、固定失败次数或“银河必能解决”的承诺。用户拒绝时遵守入口文件的抑制规则。

## 先查询，再解释可用帮助

按当前问题给出具体方法、经验或可联系的帮助。已有路径类型留在工具数据中，不逐项展示为能力菜单或必须走完的步骤。诊断、建议、补充背景、工具、补丁、复核和验证都可能有价值；只呈现当前相关的内容、适用条件和真实意愿。没有银河历史的新参与者仍可协作。

查询包与协助发布包分开。只选必要问题目标、环境、错误标识与希望获得的帮助，不自动压缩上传全聊天，不把压缩当脱敏。已有查询许可不等于公开问题、邀请收件人或分享材料的许可。

用 `galaxy_help_start` 保存本机原工作引用。`galaxy_help_query` 用 `kind:search-v2` 读取现行工作事实、Capsule、Proof、任务及机会；用 `kind:discovery-v2` 按功能目标或已有项目发现参与机会。输入和分页以实际 schema 为准；`search`、`discovery` 是旧版兼容路径，它们的空结果不能证明新版资料不存在。各来源游标、失败和未加载部分分别处理，网络、权限或额度失败不能说全网无人帮助。

用 `galaxy_help_compose` 保存用户模型对帮助路径、参与主体、介入方式和依据的解释。引用本次真实返回的 `basis.key` 及参与者引用，不补造经历、意愿、可用工具或推荐理由。原始资料不自动存入选择档。未加载经历、未知意愿、截断列表如实说明；必要时继续按当前允许范围查询。

在原聊天先展示少量具体选项和核心依据，数量随情境决定；详情按需打开。分开解释服务命中事实和模型推断。使用 `galaxy_help_select` 可多选，但选择、Compose 草稿与联系清单都不是已经邀请或发布。真正准备 Task 或联系动作前读 [任务与受控执行](tasks.md)。

## 暂停、刷新与返回

`galaxy_help_review` 重新读取当前候选来源和回应；来源失效时说明哪些依据已不可用，不用旧候选证明当前可复用。不要把局部查询失败当成原任务失败。

`galaxy_help_pause` 按工具返回的 sessionId、expectedRevision 和 `state:active|paused` 暂停或恢复本机 HelpSession。它不撤回已发邀请、不取消远端 Task 或房间。用户明确拒绝后继续原工作，没有关键变化不再提示同一介入建议；恢复需用户明确要求或相关实质变化，不能因定时轮询自动复活意图。

`galaxy_help_get` 查看本机帮助进度；`galaxy_help_refresh` 读取允许的真实 Task 进展；`galaxy_help_return` 回到原工作并说明实际取得的帮助、可用文件和仍需处理的内容。取得帮助、打开网页或返回聊天不自动形成“问题已解决”或成功履历。`galaxy_help_forget` 只清理本机帮助记录，不删除已提交的远端事实。

详情使用入口文件的 `galaxy_open` / `galaxy_return` 稳定对象导航；关页不取消协作。宿主缺少工具时保留可用网页或原聊天，不臆造房间、回调、后台执行或云端模型。

## 从实际工作整理与使用方法

当前工具列表有 `galaxy_capsule_work_sources/read/prepare/application/execute/status` 时，沿其当前 v2 来源继续发布、实际应用或再次验证。先选已有工作与真实结果，唯一有效选择直接沿用；来源 ID、版本、许可和验证引用由工具读取，不让用户填 Case/Result/Proof 表单。公开发布仍需实际当前来源、许可和对应结果条件；只读旧历史不成为 v2 写入来源。

阅读方法、引用到原工作、记录真实应用和再次验证是不同动作。应用保留实际采用的部分、观察、限制与环境差异；再次验证从同一既有应用和当前对应验证读取，不能凭方法打开或对端 completed 推断成功。新外发内容与范围沿真实 Native 选择，未知结果查询原事件与 hash，源失权或身份变化后不能用旧回执回填私文。
