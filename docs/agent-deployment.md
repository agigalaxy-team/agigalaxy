# AI Agent 部署说明

按本次选择的组件处理配置、构建和应用，不把部署步骤附加为普通开发、合并或文档整理的前提。总入口见[部署指南](deployment.md)，各组件的依赖和命令见[组件目录](component-catalog.md)。

## 配置发现与准备

从实际配置加载器和目标环境的受保护配置引用确定版本、地址、进程及数据归属。凭据只在授权进程内使用，不打印值，不写入源码、URL、提示、截图或报告；公开配置只放公开信息。

使用所选源码及其锁定依赖构建，输出放独立目录。Hub 的 `capture` 生成服务源码包，不安装依赖或部署；Native/Gateway 的 Python 编译不等于镜像构建。保留实际运行需要的构建文件、配置示例、许可和上游材料。

## 应用与失败接续

按[Linux 材料](linux-deployment-v1.md)准备发行，并按目标环境应用配置和迁移。发行尝试使用[service-release CLI](../packages/galaxy-official/scripts/service-release.mjs)规定的前后制品、配置及原操作编号；具体参数与回退机制见[发行与回退](service-release-rollback-v1.md)。

配置失败、数据库已推进和结果未知分别处理。不要盲目降级数据库或用新编号重发未知操作，先查询原回执；真实恢复按维护适配器支持范围与本次批准方案执行。维护适配器入口见[README](../packages/galaxy-official/deploy/maintenance-agent/README.md)，不从普通配置绕过尚未接通的生产恢复限制。

## 组件专用检查

只选本次改变所影响的检查，完成后集中说明结果，不重复运行未变范围。数据库、外部服务和真实模型检查使用明确的专用环境；持久化测试不能借用运行库或运行身份。

AgentOS 的数据库变量、隔离条件、Docker 与定向用例见[组件 README](../services/galaxy-operations-agentos/README.md)。这些条件仅在运行对应测试时适用；普通源码整理不需要准备数据库、模型或服务器。

常见问题是锁文件或固定上游材料缺失、配置指向旧发行、运行角色不匹配、公开入口误连私有服务，以及把进程启动或替身结果当成实际业务成功。按症状处理相关依赖和配置，保留原失败，不通过扩权或关闭安全检查绕过。
