# 第二轮工程放行与回退

本文件针对D0重构工程阶段，不能作为生产发布许可。D0通过后进入M0至M5原185项需求的实现/复核；真实用户Case与正式远程服务仍须各自验收。

## 兼容边界

旧本地身份与数据保留；只读不迁移，缺少Genesis的旧身份仍可本地读取，不冒充远端可绑定身份。旧版文件锁存在时拒绝混用，不删除锁来强行升级。Core兼容入口与既有导出保留。当前/galaxy为6项主菜单、3项查看/偏好加第4项重新初始化；默认未注入连接控制器，打开不连接。

生产认证仍是显式开发兼容profile，不称OAuth；旧凭据不能升级为更宽权限。进程内会话在关闭时丢弃，不能通过恢复旧配置复活已撤销授权。新客户端包独立于可读取本地密钥的宿主组合。

数据库六版旧迁移不重写；真实PG测试验证旧前缀升级、冲突回滚、版本缺口拒绝和备份恢复。代码回退不能附带删除新版事实或倒退迁移；恢复到隔离库、核验后按具体部署批次切换。

浏览器v1演示缓存保留不读取；v2只使用DEMO标识，不导入Core。回退网页代码不清理整个localStorage。

## 回退与恢复演练

1. 连接：取消活动操作并close运行时，撤除可选控制器注入，恢复默认只读入口。仅清理本机会话不等于远端撤销；若曾发送，按确切绑定ID另行核查/撤销，不能自动重试。
2. Core：停止写入，在一致读锁或离线状态取得完整秘密备份；不能用公开export替代私钥备份。恢复到新隔离目录核验身份、原始文件哈希与公钥配对，再试写；本轮restore-baseline测试执行了这一合成数据过程，未覆盖真实用户数据。
3. 数据库：使用受控pg_dump/pg_restore恢复到新实例，核对事实、授权、版本和权限。D0-11真实PG日志为当前验收；不得直接在生产删库/降级。
4. 源码：scripts/create-release-baseline.py生成排除秘密配置的源码检查点，并在隔离目录逐文件恢复核对哈希。记录位于outputs/release-baseline-*/verification.json；不是Git提交，也不包含生产配置。恢复代码后仍需冻结安装、运行分层验证，不能把归档完整性当应用已运行。

- 对外能力文案和发布版本；未通过功能不得写入能力声明。
