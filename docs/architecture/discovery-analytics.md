# 使用分析适配

`packages/galaxy-official/src/discovery-runtime/analytics.mjs` 集中保存既有分析请求校验、账户口径、时间窗口和 OpenPanel 结果的来源说明。`DiscoveryRuntime.analytics(actor, input)` 保留原入口，只委托该模块。

概览、路径、留存、单账户和业务量继续使用同一原生客户端；业务量本期与前期保持等长、不重叠的秒级窗口。留存仍为原生近 12 周活动 cohort，不称为注册留存；账户与混合访客口径继续区分。原生未知值仍未知，空结果不补造数据。

权限在原生读取前、结果返回前各核对一次。拆分不新增读取权限、画像来源、写入、缓存或模型调用，不改变 HTTP 路径、返回字段和错误码。搜索、推荐、索引和投递继续由原运行模块负责。

## AI agent 部署

通过现有服务运行配置发现 OpenPanel 连接和身份；秘密只由进程使用，不放进页面、日志或源码。标准服务制品必须包含 runtime 与 analytics 两个相对模块，部署沿现有发布入口，不单独启动第二个分析服务。验证使用实际入口的既有账户分析与业务窗口合同测试，并对受影响的正式分析页面作一次正常授权读取；测试替身不冒称原生数据落库。

排障先区分读取资格、未接入和原生服务错误。不要因空样本增加权限、切换模型、写入历史事件，或将 SDK 接受与原生持久化混为一谈。


## 管理界面目录

`apps/galaxy-admin/src/components/analytics/` 保存分析页面、趋势图、路径与业务图、留存/范围控件和对应样式。工作台及账户详情直接复用这里的图表；不再各维护一套分析控件。

`AnalyticsView.tsx` 继续作为 Payload 注册入口，`BusinessViewClients` 直接按原方式延迟加载目录内的分析页面。工作台和账户仍由各自页面组织，目录移动不重置已有状态或改变读请求。共享 DTO `analytics-types.ts` 与 `lib/analytics-view-model.ts` 保留原契约位置，供页面及数据适配共同使用。

部署该目录批次时同时采用三个现有消费入口的相对导入，并移除原目录中已经移动的七份实现文件；旧路径的原字节在本批来源记录保留。无需新增服务、配置、权限或数据迁移。统一管理端构建检查真实模块解析，再从工作台和完整分析入口确认图表能正常加载；不新增只镜像文件布局的测试。
