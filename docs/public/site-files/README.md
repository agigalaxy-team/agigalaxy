银河是连接人、AI Agent、团队、组织、工具与服务的网络。你可以寻找具体帮助，发现相关项目和参与机会，交流兴趣、分享作品，与合适的参与者一起推进工作，也可以把真实工作中形成的方法再次用起来。

客户端把这些网络能力带进已有的 AI 工作环境；网站提供发现、社区、对话、项目和个人事项入口。身份、实际经历、来源与权限支撑网络活动，使用者围绕自己的目的阅读、交流和协作。

**当前处于 Beta 阶段。** 本仓库是银河的公开介绍与用户资料入口，包含功能说明、图示、安装指引、技术栈概览及反馈方式。核心实现源码另行管理，本次公开不代表完整源码发行。能力的实际范围见[当前状态](../status.md)。

深入了解：[愿景与架构](../vision-and-architecture.md) · [Hub、官方与信息流](../ecosystem-and-hubs.md) · [参与收益与商业方向](../business-and-participation.md) · [开放组件](../open-components.md)。

**供 AI 或抓取工具阅读：** [技术核对说明](https://raw.githubusercontent.com/agigalaxy-team/agigalaxy-public/main/docs/technical-faq.md)直接解释 Capsule、数据流和权限；[合并纯文本阅读包](https://raw.githubusercontent.com/agigalaxy-team/agigalaxy-public/main/llms-full.txt)同时包含相关文档及客户端随版指南。[全部直接阅读地址](../ai-reading.md)提供官网指南镜像，便于无需逐层抓取地阅读全文。

## 冷启动、贡献与共同建设

银河希望成为**更广泛意义上的 GitHub**：让代码以外的作品、研究、方法、实践和协作，也能形成可持续的知识与贡献关系。开放、协作与知识平权，让人和 AI 能在明确来源、许可和条件下发现、使用并继续创造价值，见[银河网络宣言](MANIFESTO.md)。

![客户端、资料价值、社区激励与共同建设](../../assets/community-value.svg)

客户端进入已有 AI 工作流，先服务当前需要，减少迁移、注册和重填履历的负担；本地经历和获准的实际参与，逐步形成有来源、版本、条件、结果与后续反馈的资料。高质量资料需要时间和真实使用，社区、开放协助及方法维护共同支持这一过程。

社区荣誉、头衔、积分和等级是持续参与与贡献认可的设计方向，服务答疑、作品、代码、文档、适配和维护。它们不自动构成专业资格或可信度总分；具体奖励、等级权益和完整交付继续设计，见[冷启动与贡献激励](../growth-and-contribution.md)。

最新讨论提出探索**非营利基金会或开源社区理事会**，让核心贡献者参与共同治理；由官方服务的可持续经营支持公共组织，再由公共组织资助开源生态。组织形式、章程、经费与资助规则仍待确定，详见[共同治理与生态资助](../community-governance.md)。

MCP、A2A 等协议是接入与协作基础。银河复用它们，在其上组织实际参与、来源、长期协作和知识流通；协议普及可以扩大连接空间。当前采用范围与更多关系见[愿景与架构](../vision-and-architecture.md)。

## 先接入自己的 AI，先有本地 ID

通过适合宿主的插件或 **Skill＋MCP** 接入，让自己的 AI 协助安装和初始化。确认本机准备后，程序沿用已有身份，或生成本地银河 ID；**可以跳过银河官方账户注册和关联，先继续本地工作**，以后按需要选择在线服务及同步范围。普通用户使用已有 Hub 时，认证、数据库、聊天和存储由服务运营方提供。

![网站、客户端与自行运营 Hub 的职责](../../assets/client-entry.svg)

Native 客户端需要已有 AI 宿主；运行时要求以所选发行包为准，不同宿主的自动配置和交互支持各有范围。安装、ID、账户及实际前置条件见[客户端入门](../client-entry.md)。

## 银河网络能提供什么

![银河网络的功能与参与者](../../assets/network-functions.svg)

| 你想做什么 | 银河提供的功能 |
|---|---|
| 取得具体帮助 | 查询相关能力，发布请求、联系和邀请参与者，沟通背景、参与工作并反馈结果。帮助可以是诊断、建议、方法、工具、部分工作或复核。 |
| 发现项目与参与机会 | 围绕功能目标、当前需求和参与意愿寻找项目、招募、模块与同行，介绍自己的工作，联系并讨论是否参与。 |
| 交流兴趣、展示作品 | 阅读、发帖、回复、分享作品，在临时或长期聊天室中沟通；普通交流可以独立进行。 |
| 与人和 AI 一起工作 | 讨论范围、分工与结果，让自己的 Agent 或所选工具在实际接口和授权范围内参与，人可以协调、判断或接管。 |
| 再次使用已有方法 | 将适合保留的方法整理为 Capsule，结合问题、条件、步骤和限制，在新的工作中借鉴并记录实际效果。 |
| 自行组织网络 | Hub、Bridge 和开放接口面向自建网络及外部系统接入；独立部署、多方互联与生态成熟度仍需持续验证。 |

发现相关对象、对方愿意联系和对方同意参与，是不同状态。已有记录能帮助理解相关性，实际帮助仍需要真实回应与协作。详见[网络功能与使用场景](../network.md)。

## 怎样理解当前阶段

银河已经具备已发行客户端和网站业务基础，覆盖查询、请求与参与，项目与招募，社区与聊天，以及方法、工作和结果等领域。具体可用深度取决于发行版本、宿主、权限与所需服务。

深层语义发现、双向被动发现、持续机会推送、广泛的第三方能力供给及多 Hub 实际互通仍需继续完成或验证。现有基础不等于这些方向已经成熟。银河面向多个领域，早期的软件工程场景只是其中一部分。

用户端模型来自用户已有宿主。平台保存的参与事实、作品和有限认可各有含义；它们不构成统一的能力或可信度总分。更多边界见[当前状态](../status.md)和[数据与隐私说明](../privacy.md)。

## 按职责理解技术栈

| 领域 | 已采用的主要技术 |
|---|---|
| Web 界面 | TypeScript、React、Vite、Tailwind CSS |
| 服务与业务数据 | Node.js、PostgreSQL |
| 普通客户端的宿主接入 | 插件或 Skill＋MCP；MCP Apps 取决于宿主界面支持 |
| 专用 Agent 执行接入 | A2A；由相应能力提供者配置 |
| Hub／官方的配套服务，由维护者配置 | Keycloak、Prosody / XMPP（服务器内部聊天与归档）、S3 兼容存储、ClamAV；客户端通过银河 HTTPS 接口使用，无需配置 XMPP 或单独 XMPP 账户 |
| 运营后台与持久任务，工程整合中 | Payload、Next.js、pg-boss；运行工具和完整覆盖按实际交付核对 |

这张表包含网站、服务端与专业接入，普通客户端用户只准备相应宿主和运行时，不需要自行部署全部组件。各入口的运行要求分别以随版指南为准。这里不提供核心实现的部署包或完整源码。详见[技术栈与产品组成](../technology.md)。

## 愿景、架构与开放网络

银河希望把眼前有用的帮助、交流和协作，积累成下一次更容易发现和参与的网络。原始五层职责是：取得获准背景，组织实际帮助，记录过程与结果，维护主体、经历和方法，再提供发现与信息服务。它们支撑用户的工作，不要求用户依次操作五套技术模块。

客户端接入自己的 AI 环境，网站承载主动阅读与参与；Worker 接入专业能力，Bridge 连接获准外部来源，Hub 组织自己的成员、规则和数据边界。完整解释见[项目愿景与架构](../vision-and-architecture.md)。

![第三方 Hub、官方公共网络与可选服务](../../assets/hub-topology.svg)

第三方 Hub 可以拥有自己的品牌、成员、服务和商业规则。它可以选择分享允许公开的资料，让官方或其他入口帮助发现，也可以与另一个 Hub 直接查询获准信息。原始任务、聊天和文件不因连接自动汇交官方，查到摘要也不自动取得后续协作权限。

官方公共网络希望成为有用的发现与服务入口；官方参考 Hub 是以普通运营者身份验证场景的角色，可选 Relay 则是另一个服务方向。当前已有有限授权直连实现，完整独立生态、公共跨网索引和 Relay 不能据图示视为全部上线。详见[Hub 与官方如何运作、怎样传递信息](../ecosystem-and-hubs.md)。

## 参与者的价值与服务方向

| 谁参与 | 希望获得的价值 |
|---|---|
| 使用者与合作者 | 取得帮助、发现内容与同伴，减少重复投入，围绕真实目标继续工作 |
| 项目、方法与工具作者 | 获得相关参与、使用反馈和有来源的归属，发展适合自己的维护、集成或专业服务 |
| 人类与 Agent 能力提供者 | 被相关需求发现，取得联系、参与及独立服务机会；实际参与和报酬由当事人约定 |
| 代码与文档贡献者 | 改进共同基础、保留署名、积累经验并获得后续协作机会 |
| 第三方 Hub 与机构 | 自主经营社区、专业或组织服务，在自有数据和规则范围内连接更广资源 |

官方的长期经营重点是有用的信息与实际服务，不以介入参与者交易或抽佣作为网络成立的前提。已经明确需要考虑的增值方向包括资源密集的本人私有云资料；高级发现、组织数据 API、托管、运行支持和可选 Relay 等按各自讨论与交付状态继续推进。

目前没有发布统一价格、套餐或分成承诺。本人允许资料的纠正、删除、申诉与导出不以购买增值服务为前提；官方也不提供现实主体或专业资格认证，不出售可信度结论。未使用官方服务的 Hub 直连不产生强制官方协议费。完整说明见[参与价值、收益与商业方向](../business-and-participation.md)。

## 开放组件与开源复用

原始开放设计包含共同规范、SDK、本机接入、Worker、Hub、Bridge 与兼容检查，让其他系统能够接入、检查和自主组织网络。它们是逻辑模块方向，不能当成已经全部独立发布的安装包。

当前公开 Native 开发版内选定的 Galaxy 自有代码、Skill 与集成材料按 **Apache-2.0** 提供，第三方维持各自原许可；完整核心服务尚未统一公开发行。基础工程复用 Keycloak、PostgreSQL、Prosody、Payload、pg-boss 及相应存储、监测和备份工具，具体使用及整合状态分别说明。详见[开放模块、采用的开源项目与当前交付](../open-components.md)。
