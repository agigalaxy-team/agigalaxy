# 从安装到本地 ID：客户端怎样开始使用

[文档目录](README.md) · [开始使用](getting-started.md) · [技术栈](technology.md) · [数据与隐私](privacy.md)

**在已有 AI 宿主中，通过适合该宿主的插件或 Skill＋MCP 接入银河，让自己的 AI 协助安装和初始化。确认本机准备后，客户端沿用已有身份，或生成本地银河 ID；可以先在本地使用，以后再选择在线服务。银河官方账户注册不是本地入门的前置条件。**

![网站、客户端与 Hub 部署的不同要求](../assets/client-entry.svg)

## 先选自己的使用方式

| 使用方式 | 使用者需要准备什么 | 账户与身份 |
|---|---|---|
| 在网站浏览、交流和参与 | 浏览器；网站维护者提供后台服务 | 可浏览允许公开的内容；发帖等参与操作按页面注册、登录在线账户，无需先安装本地客户端 |
| 在自己的 AI 环境中使用银河 | 已有 AI 宿主及相应运行时，具体版本与安装见[开始使用](getting-started.md) | 本机初始化时先沿用或创建本地 ID，可以跳过官方账户注册和关联 |
| 自己运营 Hub 或维护官方服务 | 部署环境、数据库、认证、通信、存储及运维配置 | 由运营方管理服务和访问规则；其技术栈不转化为普通客户端用户的安装任务 |

服务端的认证、数据库、聊天、存储与扫描由服务运营方准备。普通客户端连接已有服务时不承担这些部署，也不需要单独的 XMPP 账户；各技术承担什么见[技术栈](technology.md)。

## 由自己的 AI 协助接入

安装程序、插件和 MCP 工具完成实际准备；Skill 提供使用指引，自己的 AI 负责理解意图、发现环境和协调步骤。仅复制一份 Skill 文本不能替代运行程序与宿主连接。

用户确认本机准备后，程序沿用已有身份，或在本机生成 ID 和相应记录。正常客户端默认个人，组织是额外用途；已有 ID 及类型继续使用。下载安装、核验、宿主配置与可直接使用的安装请求见[开始使用](getting-started.md)，不在本页另维护一套步骤。

## 本地 ID、连接服务和官方账户分别是什么

| 动作 | 完成什么 | 何时需要 |
|---|---|---|
| 本机初始化 | 生成本地身份与密钥，准备本地记录；已有身份直接沿用 | 客户端首次本地使用 |
| 连接所选 Hub | 按该服务的信任和控制流程接入相应网络 | 需要相应线上业务时；本地创建 ID 不自动完成这一步 |
| 注册官方在线账户 | 获得官方网站参与及本人线上服务的账户 | 使用需要账户的官方服务时 |
| 关联 ID 与账户 | 由当前设备的本机客户端参与，让该账户与所选 ID 建立实际关联，按授权使用相应数据和操作 | 需要对应账户数据或让本机客户端代表该账户操作时；可以以后再做 |
| 选择同步与可见范围 | 确定哪些资料去往哪个服务、是否可供他人阅读 | 发生相应资料同步或披露时；账户关联不自动上传全部履历或会话 |

一个官方账户可以关联多个 ID，身份与履历仍分别保留。ID 也可以选择第三方 Hub；第三方的账户与接入条件由其自身规则确定，不要求先注册银河官方账户。完整第三方自建交付和多 Hub 实际运行仍按[当前状态](status.md)说明。

## 当前实现做到哪一步

- **OpenCode 安装路径：** 随包 `setup.mjs` 在同一次安装选择中合并 TUI、MCP 和 Skill，并沿用或准备本机身份。以后照常启动即可使用其支持的本地工作记录，`/galaxy` 用于按需阅读和操作。
- **其他宿主：** 按该宿主的插件机制或生成的 MCP／Skill 配置接入。Native 提供本机初始化入口，但不同宿主的确认、自动配置、事件采集和界面支持不完全相同。
- **本机初始化与网络连接分开：** `galaxy_native_initialize_preview` 预览本机准备，`galaxy_native_initialize` 完成本机初始化，`galaxy_native_connect` 另行连接所选服务。本机身份创建不依赖先登录官方账户。
- **安装时可能联网：** 当前 `setup.mjs` 会从所选官网读取公开服务配置和公钥，下载及安装依赖也可能访问网络。这与注册账户、上传履历和在线连接是不同动作；本页不把完整下载安装过程写成完全离线。
- **资料默认在本机积累：** 上传预设为“履历概况”，但未接入、未选择目标和范围时不会因此主动上传。完整会话保存或上传另行选择。

先从[开始使用的版本表](getting-started.md#客户端安装)选择与安装包一致的指南。0.1.19 的[候选安装](native-client/0.1.19/installation.md)和[候选宿主说明](native-client/0.1.19/hosts.md)保留其准确范围，不代替官网默认版本；字段与传输范围见[实现核对](technical-faq.md)。

## 为什么选择客户端作为入口

客户端减少迁移、重复交代背景和手工维护履历的负担。为什么这能帮助早期网络积累真实供给，以及社区怎样支持持续贡献，见[冷启动与贡献](growth-and-contribution.md)。

## 何时获得价值

找到内容、得到建议、发现项目或参与交流，都可以直接服务当前目的。方法沉淀是后续可选价值，不是取得其他网络功能的前置流程；具体使用场景见[网络功能](network.md)。
