# 本机绑定回执

2026-09-10，CL-04：完成一次已确认的绑定/会话握手后，本地运行时将已核验的签名回执写入现有数据目录的 `galaxy-binding-receipts.json`。该文件与 Connection Profile、Manifest 内存和会话凭据分开管理；不修改本地 ID 或 Case 状态格式。

保存字段仅为版本、端点、主体、安装实例、绑定 ID、请求范围、绑定到期、签名回执和本机记录时间。会话 Token、会话 challenge、私钥及函数不会写入。操作复用 Core 的跨进程写锁和原子文件替换；写入前核对当前身份与配置，浏览/预览不创建文件。

## 查看与状态

- 尚未读取 Manifest 的配置接入页：第 2 项“本机绑定回执”可直接离线查看。
- 已有运行时的接入页：第 3 项管理菜单内，第 5 项查看回执。
- 可信宿主 API：`runtime.controller.listBindingReceipts()`；配置入口也提供同名只读方法，供未取得 Manifest 时读取历史。
- 每页最多 8 条，显示本机记录时间、到期、安装实例/范围是否与当前配置一致及签名核验结果。

读取只选择当前本地身份与当前配置端点的记录。历史安装实例和范围不同会明确标注。回执按所记录时间核验签名，并使用当前提供的信任键；撤销键或篡改记录显示“未验证”，超过回执期限显示“已过期”。本机记录时间不是第三方时间戳证明。任何历史回执均不证明绑定当前有效，不恢复会话或授予访问；远端核查是另一项主动操作。

重启、断开或本地 Scope 撤销后仍可查看历史。数据目录没有有效身份或处于恢复过程时读取失败，不初始化新身份。签名有效的旧回执也不能跨身份恢复凭据。

## 写入失败和容量

回执存储是已确认连接的本机记录步骤。握手成功后，如果磁盘、格式或容量导致保存失败，保持已建立的短期会话并单独显示 `receiptSaveState: save-failed`；原生页提示检查本机存储，不建议重复绑定。现有损坏文件不会被覆盖成空档案。

档案最多 128 条、读取上限 4 MiB。相同端点/绑定/签名幂等，不自动清理历史；达到容量会报告保存失败。尚未实现原生回执删除/迁出操作或保存失败后的自动重试。取消后的本机记账可能已开始原子提交，取消不保证撤回已经写入的历史记录；它不会据此恢复被取消的会话。

仅完整握手成功的回执在此保存；中断且结果未知的握手仍须独立核对，不能通过此档案假定绑定不存在。签名回执的声明字段虽不含 bearer Token，仍包含身份与端点关联，作为用户私有本机数据处理。

## 备份、验证与回退

要保留本机记录，显式将此文件加入用户的本地数据备份清单；现有云服务备份不会自动收集客户端数据目录。恢复文件只恢复历史记录，短期凭据仍不落盘。没有数据库迁移或远端导出数据集变更。

13 项相关测试通过：实际本地签名、浏览不创建文件、重启/断开不恢复会话、授权撤销后可读、过期/信任键撤销/篡改、存储损坏时会话结果与保存结果分开，以及原生查看。增加离线配置入口后，2 项配置入口测试复跑通过；严格 TypeScript 与 lint 通过。测试使用合成身份和本机服务处理器，不是生产 HTTPS 或真实宿主人工验收。

停止使用此运行时即可停止新增记录，文件可保留；恢复默认只读 Adapter 不会消费或上传历史回执。独立客户端 19 个导出保持不变，该本机存储模块不纳入便携客户端。
