# 运营资源、费用与试点证据台账 v2

本地命令读取显式登记资料，生成可交接的运营判断。它不重新登录服务器，不抓账单，不创建后台调度或备份。业务开发继续按 CUR-35；[旧试点草案](pilot-scope-v0.1.md)和[旧 integration 成本报告](integration-cost-v1.md)保留各自历史状态，不决定当前服务是否运行。

从项目根目录执行，使用新的输出文件：

```powershell
& 'C:/Program Files/nodejs/node.exe' '05-build/repos/galaxy-founding-beta/packages/galaxy-official/scripts/readiness-v2.mjs' '.' '05-build/GALAXY_RESOURCE_READINESS_R8_INPUT.json' '05-build/GALAXY_RESOURCE_READINESS_R8_NEW.json'
```

输入包含资源的拥有、配置、运行、已验证范围和容量五个维度，费用原输入、明确责任人、两类试点及读取/导出/退出证据。每个来源有路径、摘要、原观察时间、定位和范围；读取限本项目常规文件。生成拒绝覆盖，来源改变时停止，不把当前文件读取时间改成来源的新观察时间。输入不放身份秘密、私人材料正文或云账号标识，报告仅供运营维护，不自动公开。

`confirmed` 必须有完整来源引用；运行检查默认距生成不超过24小时才参与当次就绪判断。这个时间窗是报告参数，不是服务SLA，也不保证下一分钟仍在线。成本沿用 `cost-input` v1/v2：旧 v1 的明确预算保留，v2 的 null、币种、期间、来源时间和 unallocated 不改变。新增采购预算单列，不覆盖账单、不混算不同币种、不用实例金额估计整个项目或每用户费用。

CUR-33 的采用计划为最多10名受邀者、3项同时活跃协作、新增采购月上限0；不是容量测试结果。运营者名称为银河技术团队，公开联系方式仍暂不开放。事件响应、数据请求/申诉与试点协调的实际责任接受情况必须有依据，技术部署完成不能替代长期人员履责。

两类试点保留“遇阻求助并返回原任务”和“主动发现或普通交流”。工程合成数据可以检验流程，但不能计为真实用户、实际专业能力或首个真实试点。即使为输入填写真实参与者标记，若仅引用合成测试报告，也不升级真实试点状态。来源摘要和字段检查并不证明已经理解需求或取得当事人同意，仍须来源及场景复核。
