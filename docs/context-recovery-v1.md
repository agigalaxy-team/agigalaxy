# 材料草稿、提交恢复与逐次读取审计

2026-09-10，对应C12-04的本地自动开发；真人协作与真实OpenCode交互仍待复核。动态服务未部署。

## 用户流程

1. 在已确认参与者和范围的active协作中，选择“授权选定文本材料”。材料名称、正文和有效小时数在用户确认字段后存入本机；未确认输入不采集。
2. 添加或编辑1至8个片段，每段最多4000字符。可选择粘贴文本或明确指定本地文件与行号，经完整预览后加入草稿；绝对路径不保存，也不在重启时重新读取源文件，详见[文件与日志片段选择](context-file-selection-v1.md)。有效期大于0且最多24小时，最终预览还受当前binding到期时间约束。准确载荷总限16000字节，超过限额时保留草稿。
3. 日常连接菜单的“本地材料草稿与提交恢复”和发现页的“本地材料草稿”可重新打开记录。发现页支持离线编辑，不读取Manifest、不连接服务、不恢复登录。
4. 在线继续时重新读取当前协作。参与者、范围或范围确认事件变化时显示原值和当前值，明确重新审阅后才更新草稿来源。相同范围文字的新确认事件也视为变化。协作取消、暂停或不再属于请求者时保留本地材料并停止提交。
5. 预览从保存的草稿生成准确接收方、范围、期限和材料，冻结草稿ID及所有材料ID。本人确认后才能签名提交；指定提供者仍须独立确认自己的材料接收Consent。

首次初始化与身份生成交互保持冻结；新入口位于既有日常连接和协作菜单。

## 重启和失败恢复

本地`contextDrafts`保存可编辑材料与最小协作来源，`contextOperations`保存已预览的原始payloadJson、摘要、Consent意图和提交状态。两者均位于当前身份的local state，以endpoint、subjectId及事件ID隔离，沿用Core文件锁和原子写入。不会持久化访问凭据、私钥或签名。每类最多100条、合计2MiB；整个state继续受4MiB读取上限约束。

`POST /v1/context-grants/receipt`要求当前context权限和准确的kind、grantId、eventId、payloadHash，只允许原事件作者查询。结果为absent、acknowledged或conflict；acknowledged附服务端实际保存的Consent ID。授权到期、撤销或协作取消后，作者仍可核对既有事件；该结果仅表示历史接收，不证明材料当前可读。

网络失败后先对账。已经接收的事件不重复提交；未接收事件可由用户预览原内容后重试，保持事件ID、材料ID、payloadJson和原到期时间。绑定变化时创建新Consent意图；原协作、接收人、scopeEventId或材料哈希变化时拒绝复用。过期记录不自动延长期限。恢复不会自动重新授权材料或生产访问。

编辑中草稿、尚未提交的prepared记录及已确认接收的记录可在本地删除。未知或冲突结果先核对；删除只影响本机记录，不删除远端材料、不撤销既有Consent，也不能追回他人已保存的副本。远端撤销沿用原材料入口。

## 读取审计和数据边界

|访问路径|追加事件|关联|
|---|---|---|
|GET材料正文|`context.read`|材料ID、调用者、调用binding及当前生效Consent|
|GET接收前元数据|`context.metadata.read`|材料ID、指定接收者、请求者的材料Consent|
|材料列表，包括空结果|`context.query`|协作ID及当前调用权限；无单一材料Consent|
|检查授权视图导出选项|`context.export.inspect`|当前可读材料视图及Consent|
|读取授权视图导出页|`context.export.read`|当前可读材料视图及Consent|

同一内容的重复读取保留不同事件，带HTTP请求关联（如有）。审计写入与授权读取共用事务，审计失败不返回材料；审计不复制正文、标签或完整请求。授权视图可因接收尚未确认只返回元数据，导出本身不会扩大材料权限。

本人原始表数据导出沿用既有所有者取回路径及`data.export.page`审计，包含其历史提交；与按实时共享权限读取的授权视图分开。既有C18删除执行和备份策略继续适用；生产保留期限与运营决定待完成，不以本地删除宣称远端彻底擦除。
