# 事故签名信任更新与重新接入 v1

2026-09-10，本地实现，Schema29/38表不变。动态服务未部署。

C16-07 补充：原生配置运行时现在可以在明确读取服务信息时，先获取根签名的服务键清单，保存已接受的序列和撤销历史，再核验Manifest。复用现有 `acceptKeyring`、Ed25519信任链与本地运行时，没有另建身份或签名协议。

## 宿主配置

在原 `createConfiguredGalaxyAdapter(configuration)` 配置中可同时加入：

```text
rootPins: 来自独立可信渠道的根公钥 Map
trustDirectory: 独立的绝对公共信任元数据目录
trustedKeys: 该配置运行时使用的可变服务公钥 Map，初次可为空
```

rootPins和trustDirectory必须同时存在；省略两者时保留既有宿主提供服务键的行为。可信根不能从待验证服务的Manifest或同次无验证响应自行导入。目录只保存按端点划分的公共键指纹、序列、摘要和撤销历史；不存私钥或会话。Map由当前宿主管理，不与无关端点共享。

构造不联网。用户选择“读取服务信息”后，匿名请求固定的 `/.well-known/galaxy-signing-keys.json`，通过独立根签名验证并持久化，然后请求Manifest；两次请求都不发送本地ID、业务内容或会话凭据。

## 撤销与失败行为

- 已保存的新清单立即替换内存服务键，并关闭此前运行时、清空旧会话和待确认操作。
- 后续Manifest仍由撤销键签署、返回失败或用户取消，都不能恢复旧键或旧会话。取消只停止剩余读取和页面展示，不撤回已经接受的公共撤销事实。
- 服务提供新键签署的Manifest后可重新读取；需要再次预览和确认连接，不自动重连或继承旧会话。
- 重启后继续验证已保存序列；旧清单、同序列不同内容、同kid换公钥、撤销键复活都拒绝。信任文件丢失需独立恢复，不能删文件消除回滚检查。
- 验证有效期沿用已签清单和Manifest时限。本功能没有后台轮询；尚未读取新清单的客户端不会凭空知道新撤销。运营仍要通过事故通知提示重新读取，并协调所有服务实例停止旧键。

根本身泄漏或根信任发生变化时，需独立渠道重新配置可信根；服务键不能给自己授权。服务端采用现有root-pinned keyring与启动键匹配检查，部署新配置后重启。当前没有实际操作远端密钥、凭据或宿主全局配置。

## 自动化证据与回退

集成测试使用临时本地身份、真实签名绑定/session服务及独立根：建立旧键会话→保存撤销但收到旧Manifest→旧会话与未完成确认失效→新Manifest验证→明确确认重新接入→重启拒绝旧清单和撤销键复活→接受进一步撤销后取消读取，撤销仍保留。

4项相关测试、严格tsc和lint通过。当前改动只在原生宿主组合层，无SQL或便携客户端源码变化，不重复数据库或客户端打包检查。此前真实API/Worker暂停恢复及私有通知证据见 [事故站内通知](incident-notifications-v1.md)。

回退可以关闭新接入实例；保留信任目录与撤销历史。不应把撤销前的旧服务键Map恢复为可信配置。真正宿主人工验收、独立根初始配置、多实例部署、事故联系人与恢复决定仍由对应验收记录证明。
