# 协作草稿与提交恢复 v1

本地实现，动态云服务未部署。沿用现有身份、Connection Profile、Consent 和协作事件，不改变 /galaxy 首次初始化。

## 本地续填

在原生“协作请求”中，“发布求助或赏金说明”创建本地草稿；“本地草稿与提交恢复”列出当前身份和当前端点下的草稿及提交记录。重启宿主后重新打开此入口，可继续上次已确认的字段。

未连接或服务不可达时，也可从“服务信息 → 本地协作草稿”离线新建、续填和删除草稿，查看本机已有提交记录。该入口不读取 Manifest、不恢复会话或发送请求；服务端回执核对与重试需要先连接。

问题、已有尝试、请求范围、能力 ID、可见性、指定参与者、协作类型、固定金额/区间/请求报价和资格政策均保留。字段确认后才保存，输入框内尚未确认的文字不会保存。留空保留已有值，/clear 清空。字段保存不产生远程写入。草稿不包含完整 Context，材料授权仍走独立选择和确认流程。

草稿使用本地请求 UUID、修订号和步骤游标；并发修改提示重新打开，不覆盖另一窗口的版本。进入完整请求及 Consent 预览后，原始 payload、截止时间和请求 ID 一并固定保存，不能通过重启延长招募时间。删除仍在编辑的本地草稿不会删除远程记录。

## 提交恢复

所有经过宿主 AssistanceFlow 准备的请求及协作事件保存原始 payload 和 Consent 声明，状态为 prepared / submitting / unknown / conflict / acknowledged。取消等待或断网不能证明服务端没有接收。

用户选择“核对服务端接收结果”后，客户端向 POST /v1/assistance/events/receipt 发送 assistanceId、eventId 和 payloadHash。此接口要求当前 assistance 会话，只对事件原作者返回匹配的历史接收信息；其他主体查询已存在事件返回 not_found。不返回正文、Context、竞争申请或当前访问授权。原披露已撤销时，原作者仍可核对自己事件的历史回执。

- acknowledged：记录原版本及 Consent ID，禁止重复提交。
- absent：可选择预览原内容并重试，仍需逐字确认；不会自动重放。
- conflict：保留冲突记录，打开当前协作查看实际状态。

重试复用相同请求/事件 ID、正文和版本。新的绑定可重新签署相同披露范围的 Consent；不会扩大接收人或改写载荷。事件版本已变化、原请求到期或实际业务权限被撤销时，后续操作会拒绝。服务端在核对后才收到旧请求的竞态，由原事件唯一 ID 和准确回执处理，不新增第二条请求。

本地已确认接收仅说明历史写入成功，不代表协作仍可读、材料仍可访问、已付款或能力已认证。取消协作、撤销 Consent、变更范围及材料到期继续由现有 Context 规则阻断材料读取。

## 存储与适配

复用 Core 写锁和原子 JSON 写入，数据位于 galaxy-local-state.json 的 assistanceDrafts 与 assistanceOperations，按端点和本机身份隔离。没有新增数据库表或迁移。每类最多 100 条，总计最多 2 MiB，整个状态文件不超过既有 4 MiB 读取上限；清理已完成记录可释放容量。

记录仅含用户选定的请求文字、公开身份引用、Consent 声明及摘要，不保存访问 Token、私钥或签名密钥。初始化恢复或重置期间不能读写，关闭的 runtime 不能创建新草稿。本地签名仍通过原宿主受限接口执行。

独立客户端的 createAssistanceClient 增加 receipt(input, options)；既有 prepare/execute/get/query 语义不变。真实 OpenCode 人工体验和真实参与者协作验收仍单列。

2026-09-10 后续事件表单也已接通持久化和离线续填，涵盖申请报价、资格证据引用、选择确认、范围变更、交付、取消和争议等原事件类型。在线恢复先核对原版本和目标，明确确认才刷新草稿；准备后继续使用本文的固定载荷提交日志。见[协作事件草稿](assistance-event-drafts-v1.md)。独立 Context 材料草稿及逐次读取审计仍是后续工作。
