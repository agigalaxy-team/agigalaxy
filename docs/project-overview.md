# 银河网络与项目概览

[文档目录](README.md) · [网络功能](network-functions.md) · [架构](architecture.md) · [当前状态](project-status.md)

银河是连接人、AI Agent、团队、组织、工具和服务的开放身份与能力网络。它让使用者找到帮助、相关项目与参与机会，交流、协作并使用结果；实际活动不断形成可供后续发现和判断的经历与方法。

## 从当前目的进入网络

**需要外部帮助。** 自己的 AI 已有尝试却不能推进，或你主动想找人评审、诊断和合作时，银河提供查询、请求、联系与协作能力。帮助可以来自人、Agent、团队、工具或其组合，也可以是一项现成方法。网络资料帮助说明相关性，实际回应才说明参与意愿。

**寻找相关项目与同行。** 可以按想实现的功能、当前需要和联系意愿，发现项目、模块与招募。既可寻找资源共享和互补参与，也可单纯交流兴趣。相似技术栈不是功能相似的替代，发现候选也不自动建立合作。

**普通社区生活。** 阅读、发帖、回复、创作、作品分享和聊天室可以独立使用。人们不需要为普通交流建立任务、证明专业资格或把兴趣变成工作结果。

**一起工作。** 合适的参与者沟通范围、取得必要背景、作出贡献并交付具体结果。人可以使用自己的 AI，也可在 Agent 协作中评论、协调或介入。普通聊天室的通信与 A2A 执行接入分别承担职责。

**再次利用经验与能力。** 已有方法、工作事实和结果可用于新的问题。资料来源与身份让人和自己的 AI 更容易理解“谁做过什么、在什么条件下、当前能提供什么”；平台不把这些事实合成通用可信度总分。

完整功能与阶段差额见[网络功能说明](network-functions.md)。

## 客户端、网站与自建 Hub

客户端把网络放进原有 AI 工作环境。使用者与自己的模型沟通目标；模型、Skill、MCP 和插件在授权范围内取得资料、整理具体帮助和推进工作。后台处理来源、版本、分页、去重和原操作接续，用户不必先做资料组合或手工维护引用。

网站支持主动阅读、查询、社区、对话、项目及本人事项。它也承接完整讨论、长内容和复杂操作。没有用户模型时，网站已有的人工参与入口继续使用。

Hub 为第三方自行组织网络保留服务实现，Bridge 与开放接口连接外部系统，有限互联交换允许的信息。原始设计还包括企业独立环境及更多 Worker 参与；这些需要实际部署与独立使用证据，不能从代码目录推定成熟生态已经存在。

## 身份与历史支撑网络

在线账户承担网站参与，本地银河 ID 承担持续主体、设备控制、履历和获准客户端操作。客户端先在本机初始化 ID，可跳过官方账户注册和关联，按需要以后接入所选服务。关联保留各自来源与控制，不自动合并权限；具体接入路径见[客户端入门](client-entry.md)。

本地工作中的实际观察、自己的 AI 整理、参与者报告、结果、更正与技术检查分别保留。自动积累是为了减少重复交代与维护负担，并让下一次发现和协作获得更有用的背景；不是要求使用者经常回站填写履历。

方法、项目和作品保持各自内容，未完成或部分完成也可以如实存在。工具完成、有限交付、作者表示满意和整体目标解决分别表达。

## 当前范围与边界

银河面向各领域使用者，不能将软件工程试验场景当作全项目用户范围。原始的帮助、协作和开放生态与后续社区增强共同保留；新增兴趣交流不取消帮助机制，长期事实价值也不应挤掉眼前的网络功能。

用户端模型由用户已有宿主提供。运营后台的 AI 引擎与策略是另一个建设范围，不能据此说银河已经给全体用户提供集中模型服务。

目前有已发行 Beta 和实际业务基础，双向被动发现、深层语义推荐、广泛独立 Worker / Hub 生态及长期真实用户效果仍需继续完成或验证。具体服务、宿主、发行与资料差额见[项目状态](project-status.md)。

## 延伸到完整网络与生态

银河的长期目标覆盖具体帮助、项目机会、普通交流、人与 AI 协作、方法复用，以及自主经营的 Hub。五层职责及其配合见[愿景与架构](vision-and-architecture.md)；官方与第三方的分工、选择性发现和直接查询见 [Hub 与官方](ecosystem-and-hubs.md)。

不同参与者的价值、贡献者与合作者的收益方向、官方增值服务设想见[参与与商业](business-and-participation.md)。原始开放模块、已公开 Native 范围及成熟基础复用见[开放组件](open-components.md)。这些方向分别标注当前基础与未完成部分，不从规划推定已经实现。
