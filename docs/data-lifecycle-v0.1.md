# 远程数据分类与生命周期 v0.1

2026-09-11更新，覆盖C06-07/08/10及C00-05、C18关联实现。当前Schema41，共44张public表（含schema_migrations）；[逐表清单](data-inventory-v0.1.json)是当前范围，旧批次证据保留当时版本。本文件定义本地及已验证私有integration行为；公开动态服务、已确认保留策略尚未应用到生产、异地仓库状态须另行核对。

## 撤销传播时限

以撤销事务成功提交为起点。“后续读取”指提交后重新读取当前授权的请求；已经完成授权检查的并发请求、客户端已显示页面和已下载副本不能追回。部署代理须保留应用缓存头，不得把私有或授权响应加入公共缓存。

| 对象/副本 | 当前传播规则 | 时间边界与例外 |
|---|---|---|
| API当前读取、公开对象链接、Proof/Profile/履历、协作及材料 | 重查绑定、Consent、对象状态及所需来源；链接本身不授予权限 | 撤销提交后的下一次当前授权读取即受影响，不等后台清理；不是全请求原子撤回承诺 |
| HTTP对象响应 | 默认Cache-Control: no-store，包括授权查询、错误与导出；没有应用级持久对象正文缓存 | 禁止后续合规缓存存储，无法清除已显示页面或不遵守缓存头的副本 |
| 搜索来源变更 | 绑定/Consent、Case、Evidence/观察、Proof、Capsule、建设者来源变更的触发器在同一事务移除依赖候选并安排重建 | 这些变更提交时旧候选已失效；重建前后检查当前来源，旧作业不能恢复已撤销权限 |
| 搜索自然到期 | 只选择valid_until > now且built_at > now - maxAgeSeconds的候选；最大允许年龄60秒，也受Consent到期约束 | 到期候选立即被查询排除；60秒不是物理删除或队列完成SLA，停机/积压可延迟重建 |
| 派生投影与来源观察 | 查询重读原服务，索引仅候选ID；Profile撤销不回退旧公开自述，Honor保留可解释纠正历史 | 外部源站变化须先被观察到，按来源新鲜度失效；未观察变化不承诺即时到达 |
| 导出下载 | 每页重查下载记录、当前绑定、所选授权视图的原权限 | 到期/撤销后拒绝后续页；本人历史原文导出与当前授权视图区分，已下载文件由接收者控制 |
| Manifest | 公开服务元数据例外：public, max-age=60, must-revalidate | 最长60秒缓存发现元数据，不授予业务权限；仍须验证签名与当前信任 |

依据：[HTTP头](../packages/galaxy-official/src/http.mjs)、[Manifest路由](../packages/galaxy-official/src/adapters/http/routes.mjs)、[索引候选](../packages/galaxy-official/src/search-index.mjs)、[基础触发器](../packages/galaxy-official/src/infrastructure/search-index-schema-v1.mjs)、[建设者触发器](../packages/galaxy-official/src/infrastructure/search-index-builders-v1.mjs)、[原来源搜索](../packages/galaxy-official/src/search.mjs)。参见[索引说明](public-search-index-v1.md)、[材料恢复](context-recovery-v1.md)、[Honor纠正](honor-correction-recovery-v1.md)。

公开内容可能已被第三方保存。撤销使服务停止按旧授权提供后续读取，不撤销已经发生的签名事实，不保证搜索引擎、外部站点、接收者和备份介质上的全部副本被抹除。

## 保留、导出与纠正

授权有效期、来源观察新鲜度和物理保留期是三个不同参数。数据保留策略v0.1已确认，现有实现尚未按新期限调整；300/600秒等协议期限不是业务物理删除期限。

| 数据类别 | 当前保留与处理规则 |
|---|---|
| 业务事实、原签名及明确选定材料 | 默认留在主库，撤销限制使用；隐私删除按主体申请和批准期限执行。没有默认全库定时删除天数，未经选择的Raw Context不自动收集 |
| 挑战、会话摘要、绑定、Consent | 到期/消费/撤销使其不能继续使用；不等于物理清理。本人删除执行器覆盖这些记录，导出排除挑战和认证摘要 |
| 下载记录 | 最长600秒且不晚于绑定/停服截止，每页拒绝到期；Worker约60秒清理一批最多100行到期/撤销票据。停机、积压、循环阻塞可能延长物理清理，不存储服务端导出正文文件 |
| 导出审计 | 票据清理不删除data_export_reads或audit_events；按批准审计期限处理 |
| 通知 | 本人可单调推进归档截止，隐藏旧通知、删除更早已读标记；原来源事实保留 |
| 搜索投影 | 仅白名单公开字段，当前权限与候选年龄独立于物理保留；关闭索引删除候选，主体删除覆盖候选与相关作业 |
| 审计与删除回执 | 批准期限到期后可最小化终态运营原文，保留来源、操作ID、状态、政策版本、期限、计数、哈希及主体申请/取消签名、公钥 |
| 备份、下载文件、SQLite队列及日志 | 分别列入逐存储清单；主库删除结果不能替代它们的处理结果 |

当前本人导出32类数据集（含签名外部账户关联），另有六类明确选择的当前授权视图。前者可含本人撤销后的历史事实和Proof原签名并标明状态；后者每页重查原权限，不凭旧票据延续授权。不导出他人私有材料、访问凭据或服务秘密。分页是有界实时页，不是跨页事务快照；客户端保存NDJSON、页/文件摘要及未完成标记。[导出实现](data-export-v1.md)。

隐私删除和事实纠正分别处理。Case、协作、Capsule纠正追加来源化事件，更新当前投影并保留争议/纠正关联，不等于删除申请。删除不能伪造他人的认可或静默重写他人事实；引用保留逐表记录。运营者须明确实际控制者、驻留地、各类保留期限及处理依据，程序不能推定法律结论。

## 现有删除执行流程

1. 主体签署本人数据删除申请，可查询/取消。受理不等于已删除；独立运营审核填写版本化政策、主库删除时间、审计/备份期限与依据。
2. 到期执行器在维护事务中核对签名、准确批准版本、当前全部表与外键，先撤销本人授权，再处理35张本人目标表。另9张为迁移、共享运营或独立删除账本；共享Honor规则中的主体引用单独计数。
3. 跨作者引用和未到期审计可保留部分行，回执列出逐表剩余数量并支持到期续跑；作业/搜索触发器识别删除上下文，防止重建主体。
4. 已执行删除且审计期限到期后，SQLite迟到失败审计被抑制，确认后移除pending；保留期内正常交付。这不证明WAL或磁盘空闲页擦除。
5. 终态回执按政策最小化运营原文/执行明细；期限不早于历次批准的审计与备份期限，主库仍有待处理行时不能最小化为完成。
6. 准确备份快照到期清理逐仓库执行，分别记录forget/prune/check。一个仓库成功不证明全部副本删除；本机下载及外部副本不由服务控制。

命令与字段：[申请/执行](deletion-requests-v1.md)、[回执最小化](deletion-minimization-v1.md)、[准确快照清理](backup-cleanup-v1.md)。

## 恢复不得复活撤销与删除

普通数据库快照与独立删除账本均须保留。前者捕获44表及明确选定文件/SQLite在线副本；后者包含申请、审核/取消、执行与最小化记录，准确摘要和捕获截止外部保管。旧账本不能证明缺失区间没有删除。

恢复顺序：准确快照核验 → 新库隔离 → 核对事实与签名字节 → 撤销全部旧授权、下载记录并使旧挑战到期 → 独立账本补齐及重放快照后的已执行删除 → 核对各存储与当前运营配置。未执行申请只补状态，不自动批准执行。同恢复ID和同命令重试幂等，换账本截止须新建恢复候选。

隔离标记令API/Worker启动失败；重放不自动改为ready。重新开放前仍须确认账本覆盖事故截止、当前信任/密钥撤销及保留策略，处理选定对象、日志、队列及其他仓库，再安排新授权和明确生产切换。没有自动重新公开入口，不能直接把旧备份覆盖在用服务。

数据库和文件分别一致；关联写入需暂停后捕获，不声称跨存储全局原子快照。本地两个加密仓库演练不等于异地灾备。[备份恢复](backup-recovery-v1.md)、[独立账本与重放](deletion-recovery-v1.md)。
