# 身份恢复、外部账户与组织策略独立设计 v1

2026-09-11，C05-07。对应原需求：“恢复、合并/拆分、复杂组织与设备策略列独立设计；没有成熟方案时不提供‘找回’按钮。”本文件是设计交付；当前可执行能力以[绑定管理](binding-management-v1.md)为准。

## 当前模型与可执行处理

Galaxy ID的genesis把公钥、签发上下文、时间和nonce绑定到固定ID；Official的subjects保留公钥和genesis，binding是该主体在准确端点的一份有限授权。installationId是软件安装声明，一个安装可有多份binding。当前没有独立Account/Organization数据库实体，已提供OIDC外部登录及本机签署关联；尚无原ID换钥或身份合并服务，见[当前实现](identity-login-v1.md)。

| 情况 | 当前处理与结果 |
|---|---|
| 仅断开本机会话 | 清除本机会话使用状态；身份与历史回执保留，不声称服务器binding已撤销 |
| 丢失一个安装实例，另有有效绑定 | 用本人绑定管理按installationId筛选，逐份明确撤销目标binding；其他绑定保留。撤销单个binding不自动处理同实例的其他绑定 |
| 会话过期，仍持原身份密钥 | 通过正常持钥挑战建立新会话/绑定，原ID不重生成；旧Consent、旧会话和权限不因重新连接恢复 |
| 原身份密钥的可用备份仍在用户控制下 | 恢复到用户明确选定的本机身份位置后仍需正常持钥证明；当前没有一键恢复向导，本机文件恢复不等于云端授权恢复 |
| 唯一密钥及其备份均丢失 | 当前无法恢复原ID控制权；保留无法恢复的准确状态。邮箱、旧回执、公开公钥、installationId或运营口头确认不能替代原密钥 |
| 原身份密钥泄露 | 既有绑定撤销只能使这些绑定失效，持钥者仍可能建立新绑定；需按实际事故配置限制服务接入。当前没有保留原ID换钥能力，新ID不会自动继承旧事实/信誉 |
| 服务数据库从备份恢复 | 使用既有隔离恢复和删除重放，全部旧授权失效；这属于服务恢复，不恢复用户密钥控制权 |
| 删除远程本人资料 | 按现有主体签名删除流程处理主库/账本/副本；不自动删除本机身份或其他端点数据 |

事实依据：[GUID/genesis](../packages/galaxy-core/src/galaxy-guid.mjs)、[绑定验签与撤销](../packages/galaxy-official/src/bindings.mjs)、[本机回执](local-binding-receipts.md)、[数据生命周期](data-lifecycle-v0.1.md)。当前菜单提供已实现的会话、绑定查询/撤销、外部账户关联及数据处理，不新增找回、迁移或账户合并按钮。

## 外部账户关联设计

外部账户用于登录和账户管理，本地Galaxy主体用于签署事实及授权。当前OIDC关联记录使用不可混淆的`issuer + subject`；邮箱、昵称、组织显示名是可变资料。每份关联记录需要Galaxy主体ID、准确服务端点、关联版本、建立时间、当前状态、外部认证来源以及本机持钥确认依据。

关联流程：标准提供者登录成功 → 显示外部账户和将关联的Galaxy ID → 本机对准确关联意图签名 → 事务内核对两个身份与唯一性 → 记录关联回执。登录或账户恢复不能自动新建Galaxy ID、替换其公钥或生成Consent。外部账户解绑/删除后停用相应访问路径；本人签署的事实、争议和保留记录继续按生命周期处理。

Passkey、OIDC或企业SSO由成熟认证提供者及标准库承担；Galaxy作为业务资源端保留绑定、scope和逐对象授权，外部scope与本地允许范围取交集。具体标准集成属于C05-04/05/06，不能用本设计宣称已完成OAuth或受保护Personal MCP。[ADR-008](adr-008-authentication-and-protocol-profiles.md)的标准认证迁移方向继续适用。

## 换钥与恢复的后续设计

原ID与genesis保持不可变。若以后支持控制密钥演进，须增加独立、可验证的控制权版本链和所有验证端的兼容处理；不能只修改subjects.public_key。已有签名使用历史密钥与当时状态解释，新写入只接受当前有效控制版本。

可用原密钥的换钥与完全丢钥的恢复分别设计：前者需要原/新控制方的准确交接证明和版本冲突处理；后者只能依赖事故发生前已明确配置的恢复机制。恢复因子、等待期、通知/异议、撤销和退出由实际采用方案定义；未预先配置时不承诺事后找回。方案应评估成熟身份/密钥恢复组件，实施时独立核验协议，避免借用相似字段就宣称兼容。

任一控制权变更要列出受影响的端点、设备、绑定和凭据，旧凭据终止，新权限重新建立；原始事实和签名字节不重签、得分不自动转移。失败恢复候选与已经提交的控制版本区分，不能回退到已撤销控制权。具体数据表、协议及UI均待该扩展开发。

## 合并、拆分与组织

| 扩展 | 设计规则 | 应保留的事实 |
|---|---|---|
| 多个外部登录账户关联 | 建立/解除账户关系，分别验证登录及当前Galaxy控制权；不根据相同邮箱自动合并 | 每个提供者的稳定关联键、历史关联版本与操作来源 |
| 两个Galaxy主体声明关联 | 两边分别证明控制权；保留两个ID和原始作者，关系可撤销 | Case、Consent、Proof、贡献及争议按原主体归属，不能合并重写后重复计功 |
| 拆分用途或迁移新ID | 新主体获得新的身份及独立授权；只在有权范围导出/引用旧事实 | 原来源和历史签名继续引用原主体，新主体关系不等于继承能力 |
| 组织/租户 | 人、软件Agent、组织分别建模；成员、角色、服务账户与代表关系有明确版本和范围 | 离职/退组使成员访问失效，个人签署和组织来源仍可区分 |
| 组织授权与人工代表 | 组织管理员可管理组织授权范围，不能代签成员个人Consent或取得本机身份私钥 | 操作者、被代表主体、角色来源、对象和实际权限交集 |
| 组织解散或账户删除 | 先确定有权导出、业务取回、撤销和保留依据，再按逐存储处理 | 他人事实、争议与审计保留不被管理员批量抹除 |

设备管理仍以当前安装声明和逐binding撤销为基础。设备硬件证明、受管设备策略、组织远程擦除、全局自动封禁和同ID密钥演进是独立扩展，实施前需明确实际宿主能力和执行范围。当前installationId不能被解释为可信硬件身份。

## 开发阶段与验收

1. C05标准认证适配先完成提供者发现、资源受众与scope验证、明确Galaxy关联以及当前撤销检查；原生本机兼容会话保持独立入口。
2. 有实际需要后分别实现账户关联/解绑、组织成员/代表权限；覆盖关联冲突、跨主体/租户访问、退出及账户删除后的事实保留。每个扩展单独更新数据清单、导出、删除和备份恢复。
3. 换钥/丢钥恢复采用独立方案和兼容版本；验证历史签名、密钥状态变化、并发交接、错误恢复、撤销、跨端点状态不同步及真实设备体验。完整验收前不提供成功恢复的UI承诺。
4. 合并/拆分以可追溯关系和来源引用交付；验证得分去重、他人权利、撤销传播、恢复重放和退出，不能通过改作者ID完成迁移。

C05-07的当前交付是上述独立设计和准确能力边界，不改变原任务验收要求。真实身份提供者、组织运营政策和恢复方案的开发/部署继续按各自任务处理；本轮未更改身份代码、签名格式、数据库或冻结的首次初始化流程。
