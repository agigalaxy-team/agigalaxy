# 项目愿景与架构

[项目首页](../README.md) · [网络功能](network.md) · [Hub 与官方的运作](ecosystem-and-hubs.md) · [参与价值与商业方向](business-and-participation.md)

银河希望让人以更少的重复交代和寻找成本，取得具体帮助、找到相关项目与同行、交流想法，并与人和 AI 一起把事情做下去。真实参与留下有来源的经历与方法，使下一次发现和协作更容易。

网络面向人、Agent、团队、组织、工具和服务。一个参与者可以在某个问题中寻求帮助，也可以在另一个领域提供帮助。普通交流、作品分享、兴趣和社区归属同样成立，不要求每次参与都转成正式任务或商业合作。

## 从原始想法到现在

| 阶段 | 保留下来的想法 | 结合后续决定的解释 |
|---|---|---|
| 早期 AI 工作受阻的观察 | 当已有 AI 不能推进时，引入外部的人、Agent、方法与工具 | 卡住时求助是重要入口，也允许主动评审、诊断和合作；不用机械失败次数强制触发 |
| 2026-08 的核心架构整理 | 参与产生有来源的过程、结果和长期经历，逐步形成有用的信息网络 | 经历是实际活动的积累；普通参与无需先维护一份完整履历 |
| Worker、Hub、Bridge 与开放生态讨论 | 让专业能力提供者和第三方网络有独立参与、经营及互联空间 | 保留自治与互操作方向，按真实权限和实现范围逐步交付 |
| 2026-09 的网络增强讨论 | 相关项目与功能模块发现、定向招募、聊天室、自己的 AI 筛选资料 | 兴趣交流、寻找同伴和发现机会扩展原有协作，不取消已有帮助机制 |
| 2026-10 的产品与数据决定 | 全领域、论坛社区、账户与本地身份分工、可选上传和本人资料管理 | 网站可直接参与；自己的模型处理语义，程序维护来源、权限与稳定执行 |
| 当前 Beta 与后续建设 | 网站、业务服务和 Native 客户端已有发行基础，继续完善运营、宿主与生态 | 稳定程度、独立发行、实际部署和长期效果分别说明，不用一个完成百分比概括 |

这些是设计演进的整理。早期只面向软件工程、固定失败触发、官方认证或统一信誉评价等表述，不能覆盖后来的全领域、外部认证和由查阅者自行判断的决定。

## 五层职责

原始五层架构仍然有用，描述的是工作怎样形成可继续使用的结果，而不是要求部署五套服务器或让用户填写五张表。

| 层 | 承担什么 | 使用者得到什么 |
|---|---|---|
| 信息取得与本地积累 / Acquisition | 取得获准的目标、已有尝试、上下文和外部观察，保留环境与来源 | 减少重复描述，知道现有背景的实际保存范围 |
| 帮助与协作 / Resolution | 使用自己的 AI、已有方法，联系并邀请合适的人、团队、Agent 和工具 | 具体建议、复核、部分工作或共同推进 |
| 过程与结果 / Evidence Production | 记录真实尝试、介入、交付、反馈和具体核查 | 能理解谁做了什么、条件是什么、结果与未知部分是什么 |
| 共同基础 / Core | 维护持续主体、控制、权限、经历、外部凭据、有限认可及 Capsule | 可持续使用的身份、资料与方法；声明、报告和独立检查分别保留 |
| 发现与信息服务 / Information Services | 按权限查询、发现、筛选、比较资料并关注变化 | 下一次更容易找到内容、参与者、机会和相关依据 |

```text
正在做的事情／普通兴趣
  → 网站或自己的 AI 环境
  → 找到内容、帮助、交流或参与机会
  → 实际沟通和工作
  → 结果回到原目的
  → 获准的经历与方法帮助下一次发现
```

银河维护记录和依据；查阅者及其自己的 Agent 判断内容是否适用。签名、技术检查和相关性排序不自动产生银河对主体能力或可信度的裁定。

## 各部分怎样配合

| 部分 | 职责与关系 |
|---|---|
| 网站与社区 | 主动阅读、发现、发帖、回复、聊天、项目及本人事项；普通参与使用在线账户 |
| Native 客户端 | 在已有 AI 宿主中使用网络，管理相应本地身份、工作记录、所选资料及获准操作 |
| 用户自己的 AI | 理解当前目标，整理获准上下文、解释相关帮助、准备内容并接回进展 |
| 银河业务服务 | 执行业务规则、来源与权限检查、持久化和操作接续；Web 与支持的协议使用相应共同规则 |
| Worker 与 Pack | 在参与者或授权环境接入专用能力，保留版本、配置、来源及权限；安装不自动取得持续接单和敏感操作权 |
| Hub | 组织自己的成员、服务、规则和数据边界；可选择接入官方或其他 Hub |
| Bridge | 将获准外部事件或资料按明确映射接入，保留原来源与限制 |
| 开放协议与基础设施 | 复用成熟的认证、通信、数据库、Agent 接入和运维组件，银河处理自身业务语义与适配 |

客户端与网站共享网络能力，但界面各自适合所处环境。用户不必为了表现底层来源和版本机制，先手工拼接资料或维护引用树。

## 官方的长期目标

官方希望把公共银河建设成有用的发现、交流与协作入口，靠相关内容、真实参与、信息质量和可靠服务吸引使用者。长期的信息服务价值来自被允许使用的资料及实际服务能力，不来自强制收走所有原始数据。

官方也可以作为普通运营者建设参考 Hub，用同样的协议和条件验证具体场景。第三方保留自己的品牌、用户、数据边界、服务和商业模式；公共索引、可选托管和未来 Relay 都按实际使用选择，而不是所有 Hub 的必经中心。

详细关系和信息传递见 [Hub 与官方的运作](ecosystem-and-hubs.md)，模块及许可见[开放组件与开源复用](open-components.md)。

## 当前阶段

银河已有网站、业务后端和公开 Native 开发版。主要产品领域已有实现基础，完整宿主覆盖、长期运行、第三方供给与独立多 Hub 生态仍需继续推进。运营后台基础已进入工程整合，更深入的 AI 策略后台仍在研究与逐项核对。

版本及可观察状态见[当前状态](status.md)。本页描述愿景与职责，不把所有架构方块都列作已上线服务。
