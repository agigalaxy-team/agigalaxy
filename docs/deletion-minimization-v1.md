# 删除回执最小化 v1

Schema27 在原有36张表上增加最小化标记和摘要字段。终态申请（cancelled、rejected、primary-erased）可由维护命令缩减运营者原文；申请人签名、查询和旧备份补删仍可使用。动态服务尚未部署。

## 执行

使用已有 migration 运行环境，由数据库维护角色执行：

```text
node packages/galaxy-official/scripts/deletion-minimize.mjs <绝对命令路径.json> <新回执绝对路径.json>
```

命令包含 `version:1`、UUID `id`、`requestId`、服务 `endpoint`、当前 `expectedRevision`、`operatorRef`，以及 `policy:{id,version,notBefore,basis}`。`notBefore` 为秒级 Unix 时间。必须显式提供保留政策；命令到期时间与历次批准计划的审计及备份期限取最大值。存在剩余数据的执行回执不能最小化。

处理在维护事务中完成。同一命令ID和内容可重试；相同ID的不同内容被拒绝。输出写入失败不代表事务未提交，使用原ID重试并选择新输出文件。回执返回当前状态，可能已最小化，不保证与早期完整回执逐字相同。

## 保存内容

- 运营审核及执行事件的 `payload_text` 清空，原 `payload_hash` 保留。摘要存在 `retained_payload`，另有按排序对象键计算的 `retained_hash`。
- 审核说明和删除政策依据替换为带 `sha256:` 标记的摘要；决定、政策编号/版本、期限和操作引用保留。
- 执行结果移除选中行计数、撤销明细和迭代次数，并去掉零值计数；保留结果状态、必要计数和原结果哈希。
- 申请、取消的原始主体签名载荷及公钥保留；请求ID、主体关联、修订历史和最小化事件保留。新政策依据只保存哈希。

`payloadBytesRemoved` 是被清空原文的字节数，不是净磁盘节省量。摘要哈希证明所读摘要一致，不能代替已清理原文的独立验签。原有主体签名仍以原文验证。

## 恢复与客户端

账本捕获包含最小化字段。旧备份中仍有原运营文本时，恢复工具从原文计算应有摘要后与新账本比对，再更新旧事件并重放已经执行的删除。仅获批准但未执行的申请不会自动执行，恢复库保持隔离。恢复后新增的执行明细可在符合政策时再次最小化。

客户端和原生菜单支持摘要事件；菜单显示“原文已按保留期清理”。删除后持钥状态查询继续可用。客户端包须与当前源码匹配；当前61文件/20入口，仍为未公开发行的开发版0.1.0。Schema27是本功能引入版本；当前数据库Schema39，回退应用须兼容实际数据库版本。

## 范围与回退

此命令只缩减当前数据库中的运营文本和执行明细，不删除整个身份关联账本，也不擦除WAL、旧导出、旧账本文件、备份介质或外部副本。备份使用[准确快照清理](backup-cleanup-v1.md)逐仓库处理；生产捕获、定时保留与异地仓库仍需部署配置。

最小化后无法从当前数据库还原被清空原文。暂停后续调用可以停止处理；旧数据库只能恢复至隔离环境并按[删除恢复流程](deletion-recovery-v1.md)补删，不得直接恢复上线。数据库迁移仅向前；回退应用必须支持Schema27及摘要事件。
