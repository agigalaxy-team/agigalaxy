# HTTP分类额度 v1

API启动默认加载分类额度，可用 `GALAXY_REQUEST_QUOTA_FILE` 指定绝对路径的JSON文件。省略时采用下列开发初始值，数值尚未通过真实试点容量和预算测定。Schema28/37表不变；计数存在API进程内存中。

|类别|IP / 60秒|主体 / 60秒|凭据 / 60秒|
|---|---:|---:|---:|
|anonymous 公开读取|60|60|60|
|binding 绑定/会话建立|60|60|60|
|query 认证查询|600|120|60|
|submission 提交|300|60|30|
|notifications 通知|300|120|60|
|export 导出|120|30|15|
|revocation 撤销/删除申请与回执|300|120|60|

匿名和建立会话的请求未经过Bearer认证时只计IP；不会将请求体自报的subjectId用于扣除另一主体额度。公开元数据使用匿名类别。支持匿名的查询在携带凭据时先受查询类别IP限制，认证成功后再计主体/凭据。认证失败计IP，不扣主体/凭据。

同一主体的多个有效凭据共用主体额度，每份凭据另有额度。共享出口中的不同主体分别计数，但仍受较宽的IP总限额约束，不能承诺完全消除NAT误伤。业务处理失败或重复请求仍消耗请求额度；请求额度不代表已接受业务或存储配额。

## 配置与响应

配置严格包含 `version:1,windowMs,capacityPerCategory,categories`。windowMs允许1000至60000；每类别指定正整数 `ip,subject,credential`，不得省略类别，capacityPerCategory开发初始值10000、允许3至100000。容量是每类别计数键总量，IP、主体和凭据各占一个键。示例见 [request-quotas.example.json](request-quotas.example.json)。

固定窗口从该计数键首次请求开始。某维度超额返回429、`rate_limited`和按剩余窗口计算的 `Retry-After`（1至60秒）。额外的 `X-Galaxy-Quota-Category`、`X-Galaxy-Quota-Dimension` 指明类别与维度，不包含身份或凭据值。计数键容量耗尽返回503 `capacity_limited` 和短重试提示。

主体和凭据同时检查，通过后一起扣额。IP在认证前扣额，保护认证资源。各类别拥有独立计数空间；撤销、导出撤销、审计授权撤销、删除申请及持钥回执查询不占普通业务桶。撤销桶自身仍有限额。健康检查继续使用原独立配额。

客户端已有429识别与 `retryAfterSeconds`，导出客户端沿用最多两次、每次最多60秒的等待并重查授权。其他写客户端不因限流自动重复提交。503容量不足仍作为服务错误返回，不能宣称已写入。

## 部署、验证与边界

AI agent先读取现有额度JSON，确认环境与实例数，再调整数值；配置只在启动时加载，修改文件不热更新。启动记录包含实际额度政策摘要。治理双签覆盖角色/治理规则，当前额度调优不属于该签名包。

`createApi` 作为测试/嵌入接口在未传 `requestQuotaPolicy` 时保留旧 `rateLimit` IP限制；正式 `server.mjs` 总会传入已加载的分类政策。调用库构建独立服务时需显式传入分类政策。

测试覆盖认证后扣额、凭据轮换、共享IP、各维度超额、到期重置、独立撤销、计数容量、真实Case提交和撤销，以及实际进程加载政策。默认数值不代表生产容量或SLA。

当前计数在进程重启后清零，多进程/多实例不会共享计数。部署到多个实例前需共享限额后端或明确每实例预算，并另测并发上界；固定窗口在边界附近可能允许连续两窗请求。业务原文、导出票据和后台作业额度见[资源预算](resource-budgets-v1.md)；物理容量、成本、告警和生产限额校准仍按C17后续任务实现。

回退可选择先前额度JSON并重启支持当前Schema的程序；保留配置加载记录。不能通过移除生产入口的分类政策参数，声称分类限额仍有效。本批未部署动态服务、修改真实运营配置或使用实际凭据。
