# 来源化贡献风险提示 v1

当前实现已更新为 [v2 贡献来源与循环验收检查](contribution-risk-v2.md)。下方保留 v1 交付记录；全网图、计数方式和验证范围等描述仅对应当时状态。

2026-09-10，C16-03。本轮在现有 Honor 查询结果增加独立 `riskAssessment`，并接通原生 Honor 的“查看风险提示”。输入只来自该查看者当前有权读取的贡献、事件与有限 CI 证据，不增加新的身份评分或事实账本。

|规则代码|触发依据|处理含义|
|---|---|---|
|repeated-source-case|同一 Case 出现在多条不同协作记录中|提示核对重复来源；现有按 Case 去重计贡献规则继续生效|
|evidence-reused-across-cases|不同 Case 引用相同当前可见 Evidence|提示核对复用范围，不自动判定伪造|
|declared-related-parties|现有规则已将请求者和提供者声明为关联方|提示非独立关系；不推断未声明关系|
|concentrated-participation|同一贡献主体在小于 60 秒内确认参与至少 20 条不同协作|提示复核集中活动；批量操作也可能合法|
|accepted-work-under-review|来源保留过 accept 事件，当前又存在纠正、争议或暂停|提示不要仅凭历史验收声称当前成功；不认定当事人欺诈|

政策标识为 `contribution-risk@1`，集中活动阈值包含在响应中。它是当前固定的提示规则，不是生产限流或封禁策略。返回关联 Case、Assistance、事件和 Evidence ID，允许回溯来源；排序和去重不改写原事件。

## 与事实、权限和撤销的关系

`riskAssessment` 与 `card`、`contributions` 分开。`fraudDetermined` 和 `automaticPenalty` 固定为 false，不改变贡献计数、Honor 资格、排名、Proof 强度或协作状态。当前没有全局欺诈分数、自动裁决或自动处罚。

用户无权查看的来源不会参与提示生成。来源被撤销、过期或纠正后，下次查询按当前可见数据重算。原生菜单明确标注“仅供复核”，每条提示展示所依赖的来源 ID。扫描不完整时返回 `incomplete-source-scan`；没有可见提示只表示该范围没有命中规则，不表示主体可信或不存在问题。

缺少 CI 不能单独推断虚假成功；已有纠正/争议触发的是审查提示，不是真伪结论。当前范围是所选能力、社区和时间窗内的可见协作，尚未覆盖全网互证图、独立验证者的行为归因、恶意工件内容检测或运营案件裁定。C16-04/05 的双向处理与证据补充继续单独推进。

## 接口、验证与回退

复用现有 `/v1/honor/query` 和 Honor 状态接口；客户端透传新增字段，旧客户端可忽略。无新路由、数据库表、迁移或凭据范围。纯计算模块位于 `src/domain/contribution-risk.mjs`，不进入便携客户端依赖图；19 个客户端导出不变。

4 项相关测试通过：规则分类与输入不变、集中活动阈值/窗口/去重、原生风险页面、真实本地服务→HTTP→客户端→宿主查询。集成检查涵盖同源去重不重复计贡献、关联方提示、公开查看者不获得私有风险来源、争议提示及授权撤销后提示消失。lint通过。没有改动SQL，未重复运行PostgreSQL全层，也未部署动态服务。

关闭新增查询字段和原生菜单即可回退提示功能；现有事实、授权、暂停及计数规则保留。生产运营阈值、真实案例与人工处理验收尚未完成。
