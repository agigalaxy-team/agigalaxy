## 隔离复现阻塞

NATIVE-006 的隔离组件复现尝试被平台安全执行检查拦截，没有获得成功测试结果。仅存在用于准备的固定源码副本，不能据此认定测试执行成功。未通过其他工具或改写请求绕过该限制。

因此本项仍为静态确认，动态验证状态为 **blocked（受阻）**。其他条目若未提供独立执行记录，均为 **not_run（未运行）**，不能用静态推演替代动态验证。拟议回归只使用合成身份、假传输或可销毁隔离目标；不读取生产数据，不运行真实模型/客户端任务。

## 首批复核后的回归精度

- WEB-L003：正常资料包准备流程会拒绝无效复制许可。负例必须模拟外部导入者构造的、外层格式与签名有效的容器；目标是错误的原作者验证状态，不是复制许可或线上授权绕过。
- NATIVE-006：使用两个独立宿主/桥接实例共享存储，不能用单一请求通道顺序执行来排除跨实例竞争。
- IDENTITY-001：撤销来源批准绑定时，应保留另一个仍有效的导出绑定，否则只能证明导出认证被拒绝，而没有覆盖正文许可缺口。
- NATIVE-004：区分底层 rpc.close(ctx) 可因取消返回，与后台清理/写入卡住；上层 Close 在调用 rpc.close 前等待 interrupt 请求的路径也应验证。
- NATIVE-005：假权威响应保持签名历史合法，仅变更未被绑定的投影字段；不将受信权威异常场景说成任意公网身份接管。
- 所有权限失效测试均应把授权停止与异步擦除分开，验证正文仍保存时也已不可再读；不以“清理恰好完成”掩盖授权问题。
