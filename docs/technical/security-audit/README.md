## 工作分解

1. 建立逐文件清单，冻结 blob SHA，识别适用 AGENTS、生成代码、依赖锁、二进制及上游材料。
2. 身份与权限：账户、设备、会话、认证、授权、撤销、跨租户访问及管理边界。
3. Go 业务与数据：任务、协作、聊天、文件、迁移、事务、队列、重试与原操作恢复。
4. Native 与宿主：本机身份、恢复、文件路径、进程调用、本地监听、MCP、来源信任与用户确认。
5. Web 与后台：BFF、Cookie、CSRF、CORS、XSS、服务端请求、上传、浏览器密钥及 UI/后端状态一致性。
6. AgentOS 与专业服务：模型和工具权限、非可信资料、回调、密钥与日志、测试数据库隔离、A2A。
7. 供应链与运维：依赖锁、构建工作流、部署脚本、容器、配置、可观察性、备份与恢复。
8. 跨域复核：追踪实际调用链，交叉复核候选问题，剔除误报；核查期间 main 增量并单独标注覆盖。
9. 报告收束：核对总数、未审阅项、阻塞、发现证据、修复建议、验证方式与最终提交。

## 覆盖台账要求

每文件至少记录 path、blob SHA、文件类型、审阅责任域、读取范围、检查内容、结论、证据、发现编号及验证状态。状态分开维护：

- 内容审阅：not_reviewed / in_progress / reviewed / blocked。
- 验证：not_run / passed / failed / blocked / not_applicable。
- 发现：candidate / confirmed_static / confirmed_dynamic / rejected / accepted_limitation。

“reviewed”仅表示对指定版本和范围完成内容审阅，绝不表示该文件不存在任何漏洞。生成文件、依赖锁、二进制和第三方文件不静默跳过，分别记录生成来源、消费路径、版本与许可、格式与敏感资料检查方式以及无法验证的内容。

## 发现记录格式

每项发现必须有编号、标题、优先级及理由、受影响版本、文件与行号、前置条件、输入到危险操作的数据流、实际影响、现有缓解、证据、复现或验证状态、修复建议、最小回归方案及复核结论。未经核验的猜测不得作为已确认漏洞；已有历史问题必须对当前基线重新验证。
