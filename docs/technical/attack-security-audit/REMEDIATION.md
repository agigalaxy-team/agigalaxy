# 修复建议和验收条件

以下是可核对的防御验收标准，不是已完成修复或已通过测试。任何执行验证须另有明确授权与适用平台许可；此文不要求恢复已被中止的验证。

## A03 搜索与聚合预算

- 改为直接授权后解析引用并判断查询成员关系，或在单次请求内只重建一次完整快照；不得以缓存绕过当前可见性和授权。
- 对内部页数、累计工作与总耗时建立显式上限；预算耗尽时返回有界 unavailable/indeterminate，不无声继续。
- 直达与 information 包装器计量同一种真实工作；聚合项和内部页均计入总预算。不同 key 的相同来源去重只能辅助，不能替代总预算。
- 静态验收：正常生产调用链都接入预算；无需依赖“省略 after”才触发计费；错误折叠不会重置预算。
- 将来获准的隔离回归需证明：缺失引用、早命中、语料变化、取消、8 项重复选择与不同查询均遵守总限额；权限不同的调用不能共享越权结果。当前均未执行。

## A02 来源图解析

- 为一次请求缓存已经完整授权的来源解析结果；缓存键覆盖身份、版本、case 和授权上下文，不能缓存半成品或未授权结果。
- 独立保留递归栈循环检测，另设总节点、边、深度及总耗时上限。
- 输入引用去重有帮助，但菱形 DAG 即使边不重复仍可共享后代，不可仅靠去重宣告修复。
- 静态验收：每个有效唯一节点的昂贵解析在同一授权上下文内有明确次数界限，授权变化仍按政策失效。
- 将来获准的隔离回归应覆盖共享后代、重复引用、深链、权限撤销、版本变化、取消与错误，不需制造资源耗尽。当前均未执行。

## A01 归档累计存储

- 按真实账户对官方与设备来源归档执行有限字节/数量预算，并补充服务总量准入控制。
- 预算检查、预留、块写入和计量变更需具备并发原子性；不能简单把账户 ID 传给仅按 origin_subject_id 的旧统计。
- 给未完成上传定义有限生命周期，与用户已完成归档的保留偏好分开；明确删除和失败回滚如何释放预算。
- 静态验收：所有 create/chunk/complete 等增长入口均走预算，官方 nil-origin 行被正确计入，原有所有权/CSRF 不退化。
- 将来获准的隔离回归应覆盖跨多个归档累计、并发写入、幂等重试、边界块、删除回收、失败事务和未完成上传到期。当前均未执行。
