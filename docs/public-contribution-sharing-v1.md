# 公开贡献事件与 Honor 分享 v1

2026-09-10，本地实现；Schema38 / 43张表，无新增迁移。对应 C13-03，并推进 C13-04。动态服务未部署。

## 原需求与实现

[开发清单](../../../GALAXY_OFFICIAL_BASIC_CLOUD_DEVELOPMENT_CHECKLIST_v0.1.md) C13-03要求：“Honor卡片可核验证据与撤销状态，分享遵循可见性；过期截图不能作为最新证明。”C13-04要求排名限定领域、社区、窗口和门槛。

原协作服务强制所有后续事件使用Private，而Honor公开投影要求贡献事件逐条公开可见，导致公开榜单只能被抑制。本批复用原协作事件、Consent、本机签名、审计及Honor投影；不另建贡献事实表或奖励系统。

请求本身公开时，作者可逐条选择公开参与确认、范围变更及确认、交付、验收、取消、争议、解决建议及确认。每次选择只作用于这条事件，默认仍为Private。申请、选人、名单、邀请、报价维持原私有处理；Context使用原独立授权。后续[C12通知与请求者履历](notifications-requester-history-v1.md)已增加提供者主动选择公开结束后反馈的流程，默认仍Private，反馈不计入本页Honor贡献规则；该后续版本使用Schema39。

客户端读取当前协作并检查事件类型和请求状态，预览固定事件全文、Public、public-profile、端点、有效期及确认文本。只有准确确认后才签署并发送Consent和事件。服务端重新检查；低层调用也不能公开私有请求中的事件或公开竞争申请。

历史Private事件不会被改写。某条关键贡献事件仍私有时，匿名Honor不纳入该协作；参与者仍按自己的原授权读取。根请求公开不代表所有参与者同意公开贡献。

## 宿主与客户端

- 原生事件草稿新增“预览公开贡献事件”，保留原“预览事件与授权”；随后走同一个完整预览及精确签名确认。
- 无草稿的直接事件入口提供本次Private/Public选择，再确认准确内容。
- `prepareCollaboration({assistanceId,event,eventVisibility:'Public'})`提供相同能力，也支持原`draftId`/`draftRevision`。省略`eventVisibility`保持Private。
- 旧草稿缺少来源可见性字段时按Private解释；重试沿用已保存授权的可见性。首次`/galaxy`初始化交互未修改。

## 榜单与当前状态

只有当前公开且满足原领域/社区、窗口、证据和最小群组门槛的来源进入榜单。同Case去重、有限CI事实、关联方标注和并列名次沿用原规则；不授予接单资格或个人能力认证。

隔离工作流通过真实HTTP API、客户端及宿主控制器创建五位提供者的十五个合格公开Case，另外保留私有验收和私有请求。窗口关闭后返回五人并列第一、15个公开Case，关联方贡献单列。撤销一条公开验收后，某成员不足三个Case，合格群组不足五人，榜单被抑制且不返回小群组统计。

同一状态链接可匿名读取当前卡片：撤销后Case数更新；规则到期后显示inactive-rule；卡片ID保持稳定，checkedAt更新。旧截图不代表当前状态。Case/任一协作授权失效导致整串不可用的原有语义继续保留。
