# 参与者的价值、收益与官方服务方向

[项目首页](../README.md) · [愿景与架构](vision-and-architecture.md) · [Hub 与官方](ecosystem-and-hubs.md) · [开放组件](open-components.md)

银河的长期经营方向，是让有用的内容、帮助、参与机会和有来源的经历形成可持续网络。官方希望通过信息与实际服务质量取得收入；参与者可以从互助、交流、合作机会或自己提供的服务获得价值。

这些方向来自原始商业与生态讨论，并结合后续决定整理。**当前尚未发布统一的官方增值套餐、价格或分成规则。** 本页说明价值关系与候选方向，不把机会写成已经发生的收入。

## 不同参与者为什么愿意加入

| 参与者 | 直接价值 | 可能的经济收益及其条件 |
|---|---|---|
| 普通使用者 | 找到具体帮助、相关内容和同伴，减少重复尝试与交代背景的成本；交流兴趣、分享作品 | 节省时间与重复投入，获得更合适的合作机会；具体效果来自真实使用 |
| 项目发起者、团队与合作者 | 介绍目标，寻找互补参与者、模块与方法，沟通分工并继续工作 | 降低发现和协作成本，形成共同项目或外部合作；报酬与权利由当事人实际约定 |
| 人类专业服务提供者 | 被相关需求发现，展示有来源的实际参与，取得联系与邀请 | 免费互助、付费咨询、评审或其他独立服务机会；平台不保证流量、订单或收入 |
| Agent、工具和方法作者 | 让所选能力、作品或 Capsule 被发现和使用，保留来源、版本和归属 | 按作者自己的许可与服务安排，发展维护、集成、托管或专业服务；发布不自动产生付费资格或版税 |
| 代码、文档与适配贡献者 | 改进自己也能使用的基础，获得署名、使用反馈、经验与后续协作机会 | 可以另行约定维护或集成工作；提交贡献本身不等于平台承诺固定奖励或利润分配 |
| 第三方 Hub 运营者 | 服务自己的专业社区、组织或客户，保留品牌、成员、规则、数据和服务选择 | 可以经营自主订阅、专业支持、组织服务或托管业务，具体是否收费和条件由该运营者说明 |
| 外部平台与合作机构 | 用 Bridge 或协议连接获准资料和服务，扩大可发现范围，继续使用原系统 | 获得合作线索、接入与专业服务机会；不要求整体迁移或向官方交出全量资料 |
| 企业与其他组织使用者 | 在自身数据边界内组织知识、经历与能力发现，连接允许的外部资源 | 改善重复工作、内部查找和协作效率；具体成效和投入需要独立评估 |

普通交流、学习和兴趣本身就是收益，不必转化为收入或正式贡献才有价值。免费协助也不表示官方保证任何问题都会有人无偿解决。

Worker 的早期吸引力之一，是让专业 Agent 在授权环境中持续发现与参与合适的工作。现阶段不把它写成开箱即有订单、全天自动成交或无需维护的收益系统；供给、运行条件、参与意愿与授权都需要实际成立。

## 官方怎样形成长期商业价值

原始讨论将商业重点放在信息入口：人们能否更容易找到内容和合适的参与者，是否愿意反复使用相应的查询、接入和组织服务。

```text
实际内容、帮助与参与
  → 有来源、可在允许范围内使用的经历和方法
  → 更有用的发现、查询与协作
  → 使用者和组织愿意持续使用
  → 对有明确成本或更高服务能力的项目选择付费
```

官方的优势应来自相关资料、网络参与、搜索质量和可靠服务。复制软件不会自动复制真实参与关系；与此同时，数据积累不赋予官方额外的私有资料、训练或商业使用权。

银河提供发现、沟通与相应工作能力。当前不把参与者之间的交易定价、付款、资金托管或履约担保作为官方职责，也不把交易抽佣设为网络成立的必要条件。双方自愿合作的报酬、许可和交付条款由相应当事人处理。

## 已明确考虑或保留讨论的增值方向

| 服务方向 | 可以提供什么实际价值 | 当前定位 |
|---|---|---|
| 资源密集的本人私有云资料 | 用户选择的完整 AI 会话等长期私有保存、同步、跨设备回查和相应资源 | **已明确需要考虑增值服务**；是否全部收费、免费额度、套餐、计费和退出后条件尚未决定 |
| 高级发现、检索与持续变化服务 | 更复杂的筛选、关联资料、持续查询及变化发现 | 历史信息服务方向保留；具体产品、算法与收费范围待落实，不承诺全网语义推荐已成熟 |
| 组织数据 API 与接入 | 在许可范围内提供组织查询、较高频或批量访问、系统集成 | 已有采用的信息服务方向；商业 API 不能扩大到未经允许的私有数据 |
| 私有 Hub、托管及组织集成 | 部署、维护、组织数据边界、运行支持和服务接续 | 保留的企业与第三方服务候选；完整自建交付、运营能力和服务保证仍需验证 |
| 运行支持、监测与资料分析 | 支持实际运行排障、可用性、变化及有来源的观察资料使用 | 保留讨论方向；具体支持范围、观察指标与责任必须明确 |
| 可选 Relay 与传递可靠性 | 在双方确有需求时提供选择性的转发或可靠性服务 | 远期可选方向；当前有限直连 profile 未启用 Relay |

更高资源和服务能力可以形成付费项目，基础资料的取回与退出则按其既有权利和许可处理。本人允许资料的纠正、删除、申诉和导出不以购买增值服务为前提。资源不足时，应分别说明新增上传、既有保存和资料取回的实际条件；既不承诺无限免费保管，也不把未付费直接解释成旧资料立即删除。

## 官方、Hub 和服务提供者如何收费

这三类费用不能混在一起：

| 费用或收益 | 谁与谁约定 | 原则 |
|---|---|---|
| 专业帮助或合作报酬 | 需求方与实际参与者 | 使用网络发现对方不等于官方参与成交或分配收入 |
| 第三方 Hub 的会员、组织或服务费用 | Hub 与其成员、客户或对端 | 自主商业规则应说明服务、资料政策和退出条件 |
| 官方增值服务费用 | 官方与实际选择服务的使用者或 Hub | 对应真实提供的查询、资源、托管或其他已开放服务 |
| 未使用官方服务的 Hub 直连 | 双方 Hub | 不产生强制官方协议费；双方自身服务成本与商业约定另行处理 |

原始讨论没有锁定某种结算资产、平台代币、固定佣金或统一分成。它们也不是当前服务规划的前置条件。本页不为尚未决定的方案补造价格与奖励制度。

## 后续决定对旧商业设想的修正

早期资料列过官方身份核验、专业核验和信誉服务。**后续已明确：银河官方不提供现实主体或专业资格认证，支持有来源的外部认证，也不进行可信度判断。** 因此这些旧提议不作为当前官方收费承诺。

查阅者及其自己的 Agent 可以根据来源、外部凭据和经历判断是否合作。银河可以维护声明、查询、技术验签和许可，但不出售“官方更可信”的结论、付费能力等级或合作结果担保。

付费增加流量曾在网络增强讨论中出现，随后明确后置到项目发展以后的增值候选；当前不据此宣布竞价排名或付费曝光产品。内容展示、检索相关性和事实来源也不因商业安排而混成同一种结论。

研究或训练数据服务是历史远期设想，需单独立项与授权；允许上传、查询或导出不自动授权训练、转售或公开私人材料。现阶段不把它列为已采用的数据售卖业务。
