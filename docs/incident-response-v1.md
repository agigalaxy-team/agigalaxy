## 当前实现

API 和 Worker 启动时从显式绝对路径 `GALAXY_INCIDENT_FILE` 加载同一份 JSON。文件不含身份材料、凭据或私有事故正文。未配置时保留原行为。

`contained` 与 `recovery` 都阻止业务发布、共享读取、导出下载、Docs MCP 及新 Evidence 作业；未知新增路由也不会默认放行。健康探测 `/healthz` 仍返回200，`/readyz` 返回503。过了某个时间不会自动恢复。

保留 `/v1/service-status`、Policy 与签名键状态读取；已有 binding 的 session 建立、binding/Consent/Proof/Context 撤销、导出票据撤销、审计授权撤销和删除申请仍走原处理器及身份权限检查。新的 binding 和业务 Consent 创建不放行。事故开关不批量撤销授权，也不替代现有签名信任链。

`/v1/service-status` 添加 `incident`（ID、revision、state、更新时间、公开说明）；顶层 businessWritesAccepted/downloadsAccepted 同时受事故与退休政策约束。当前通知是使用者主动查询公开状态，未实现按受影响主体推送，也未向邮件或外部平台发送消息。

启动配置审计记录事故ID、版本、状态、更新时间与完整配置摘要，API/Worker分别保留历史；不记录公开说明全文或恢复材料正文。重启可加载同版本同摘要；同版本改内容、倒退或跳版本拒绝。活动事故不能通过删除配置或换ID解除；恢复采用同ID的下一版本，并提供恢复检查时间与证据文件SHA256。证据摘要用于定位运营检查记录，程序不会因为存在摘要就认定其内容真实。

## 配置字段

|字段|要求|
|---|---|
|version|1|
|id|运营选定的事故标识，字母数字及点、下划线、连字符，最多80字符|
|revision|从1开始；每次内容变更递增1|
|endpoint|实际 HTTPS origin，必须与进程 GALAXY_ENDPOINT 相同|
|state|contained / recovery / resolved|
|updatedAt|已发生的 Unix 秒时间，不能将恢复安排在未来自动发生|
|publicMessage|最多1200字符的明确公开说明，不能填原始日志、用户材料或秘密|
|recovery|暂停时可为null；resolved要求 `{checkedAt,evidenceSha256}`|

## AI Agent 处置步骤

1. **隔离**：确认实例、域名和事故范围，记录事故ID；准备 contained 配置。先隔离入口并停止/排空旧 API 和 Worker，再让各实例加载同一配置。配置不是热更新，修改文件不会撤回已在途的请求或作业。严重泄漏时先停止进程，不等待请求自然结束。
2. **确认停止**：逐实例查看实际加载的 runtime_config_events 和服务状态；业务读写返回503，健康探测200、就绪探测503；确认没有旧 Worker 继续领取任务。不要只看负载均衡器的单次响应。
3. **收回权限**：用现有授权主体撤销具体 binding、Consent、Proof 或 Context；保存对象ID和审计引用。事故暂停和解除都不修改这些撤销记录。若访问凭据已失效，现有主体可签署新的短期session用于撤销；全失去身份控制的案件需运营处理，不扩大普通管理员权限。
4. **签名事件**：若服务签名键泄漏，停止使用该键的所有进程，按现有 root-pinned keyring 机制发布撤销/替换序列并重启；确认客户端收到新信任状态。此时不能依赖受损签名实例提供可信公告；使用独立运营渠道。根键泄漏需要独立重建客户端信任，不能以服务键自签解决。
5. **通知**：publicMessage只发布必要状态、影响范围与操作建议；使用既有运营渠道联系受影响者，记录实际发送回执。公开状态可查询不等于当事人已被通知。自动化不得把私有对象清单放到公共状态；本实现没有自动外发通道。
6. **修复与恢复检查**：保持 recovery 状态，在隔离环境完成故障修复、恢复及删除记录重放。确认撤销仍有效、旧凭据拒绝、业务闭环和Worker正常，将实际结果归档并计算摘要。数据库恢复沿用 [备份恢复](backup-recovery-v1.md) 和 [删除重放](deletion-recovery-v1.md)，不能恢复已撤销访问。
7. **明确恢复**：填写 resolved 下一版本及检查引用；所有实例先加载连续的事故版本，再按发布流程恢复流量，查询状态和就绪探测。解除后重新演示一次撤销对象无法访问及新业务可创建。API/Worker版本不一致时先保持隔离，补齐中间配置加载记录，不能跳版本。

回退：再次发布 contained 下一版本并停止旧实例。不要直接删除活动文件或回退事故版本；已解决事故可以在后续加载中移除配置，但原数据库记录保留。旧服务不支持新审计字段，回退应先隔离并使用兼容的新版本修复，不降数据库版本。
