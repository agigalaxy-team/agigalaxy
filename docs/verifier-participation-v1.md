# 验证者参与案件与双向处理 v1

2026-09-10，C16-04/05 本地实现。复用现有 Moderation、签名 Consent、本人导出和审计，不新增表或数据库迁移；当前仍为 Schema 37、42 表。动态服务未部署。

## 参与与复核

普通 Case／Evidence 案件和 Assistance 案件共用以下追加事件：

|事件|谁可以执行|结果|
|---|---|---|
|invite-verifier|当前配置且不参与本案的处理者|签署验证者 Galaxy ID、准确报告来源目标、复核范围和邀请有效期；不替对方接受，也不授予来源权限|
|accept-verifier|受邀本人|明确签署同一 invitationId 后取得本案参与角色，可以补充说明和申诉|
|decline-verifier|受邀本人|拒绝邀请；未接受前不成为当事人，邀请撤销后仍可记录拒绝|
|withdraw-verifier|已接受的本人|退出当前复核，停止提交新复核意见；保留原记录及本人申诉、补充和纠正权|
|verification-response|已接受且当前能读取邀请与来源的本人|签署 supported／unsupported／inconclusive 意见、说明和最多 8 项引用；保留多次意见的顺序|

邀请的 target 必须匹配原报告的 Assistance ID，或准确 Case ID／报告版本／来源事件 ID／可选 Evidence ID。邀请者还要能读取报告与来源。Case 后续版本可以变化，原报告版本及邀请目标保持不变；来源页同时显示当前版本供复核。

每个案件最多邀请 4 个不同身份；原有最多 100 个报告版本和 3 次申诉限制保留。邀请本身不超过 7 天且不能超过其 Consent 的有效期；原生入口接受 1–60 分钟输入，仍受当前绑定/授权有效期限制。过期、被拒绝或退出后的再次邀请产生新事件；接受和回复必须指向当前邀请 ID。旧记录不覆盖。

## 三方权益和意见强度

Case 所有者、Assistance 的实际请求者/选定提供者以及报告者沿用原角色。Case 中他人填写的“参与者”不是验证者本人确认，不据此赋予验证角色。邀请只能由配置处理者签署，接受必须由受邀身份的当前会话签署；不能自己给自己创建验证岗位。

接受后，验证者能提出本人工作、材料或复核方面的补充，纠正本人文字，以及针对处理结论申诉。即使随后成为全局 moderator，参与过本案的验证者也不能裁定或重验自己的案件。当前排除依据是系统记录的身份和参与关系，不证明现实中没有关联方。

当前还排除受邀身份处理其被邀请的同一案件，避免邀请与裁决角色混用；此限制不赋予当事人身份或任何来源读取权。

复核意见返回 `authority: participant-signed-review`、`independenceVerified:false`、`capabilityVerified:false`。这是可追溯的本人意见，不自动产生 CI Evidence、Proof、Honor、能力认证或处理结论。文字纠正保留原意见；如需改变复核意见，应另提交新的 response。Evidence 的实际重新采集和 Proof/Profile/Honor/Search 更新仍走已有独立处理者签署的 `revalidate` 工作流。

## 可见性与退出

邀请只带签署披露的目标和复核范围，原举报正文继续遵守其原 Consent。受邀者能从处理队列找到邀请，并在原生页面和提交预览中看到准确范围。邀请不会自动授予完整 Case、Assistance 私有事件、Evidence 或 Context 权限。

可以接受参与后等待材料共享；缺少当前来源权限时不能提交复核意见，仍可退出或提出自身权益说明。邀请/来源授权撤销后，新意见被阻断；历史参与和申诉权继续保留。其他未受邀身份不能通过案件 ID 或队列取得处理视图。

邀请和正式复核意见的接收者在精确签署预览中列出：配置处理者及已有当事人，邀请另加受邀身份。已参与者的补充、文字纠正和申诉默认仅向配置处理者披露。其他处理决定按原规则向当事人披露。每条正文在读取、来源沿革和授权视图导出时重新检查其 Consent；撤销后隐藏正文，不删改原事件或自动撤销操作性暂停。

## 持久化、审计和客户端

处理状态仍为 open／resolved／appealed。新报告从 open 开始；pause／resume 只改变暂停标记；resolve 进入 resolved 且不自动解除暂停；仅当事人可从 resolved 申诉进入 appealed，最多三次。补充、文字纠正和验证者参与事件不改变状态或暂停标记。新裁决保留旧裁决，所有事件递增同一报告版本。

参与状态从已有 `moderation_events` 的签署邀请、接受、拒绝和退出记录重建；不新增可手动编辑的身份名单或奖励账本。Case／Assistance 查询均纳入受邀身份自己的处理队列。准确事件重放返回原回执，后续退出或加入其他参与者不会重复写入原事件。所有新事件复用 `moderation.event` 的执行者、绑定、Scope、Consent、HTTP request 和幂等审计上下文，审计中不复制意见正文。

本人事件数据集及 `authorized-views` 沿用已有导出功能，保留原作者；验证者的补充不会变成请求者的数据。无需新 Scope，继续使用 moderation／consent；来源、Evidence 与 Context 的读权仍独立。

`/v1/moderation/config` 以 `verifierParticipation:1` 声明支持。客户端会检查支持标记和当前可执行动作，在准确预览后签署提交。旧客户端仍可使用原报告/处理事件；新客户端不会向未声明支持的服务发新动作。原生入口为现有举报处理队列或 Case 独立争议处理，冻结的 `/galaxy` 首次初始化不变。

## AI Agent 升级和验证

升级服务、便携客户端和项目内原生 Adapter，沿用现有数据库角色与服务配置。当前服务 API 角色仅追加新事件和更新既有状态字段，不增加数据库写权限。新客户端安装包需要重建，使用离线独立消费者验证新增事件结构和全部 20 个入口。关闭新邀请入口可以暂停新增参与；回退到不识别参与事件的旧服务会失去这些身份的队列/角色派生，因此应优先前向修复，保留源事件后恢复兼容读取。

相关工作流覆盖 Case 和 Assistance 两类目标、签署邀请与接受、客户端之外的越权裁定/来源读取拒绝、意见和私有补充、本人纠正、结案/申诉/新决定、退出与原回执重放、正文撤销、授权导出及审计。隔离 PostgreSQL 使用现有受限 API 角色，并验证原事件不能被该角色改写或删除。

真实 Requester／Provider／Verifier 参与、运营处理规则和现实独立性、实际 OpenCode 体验及原发布验收继续单列。本实现不承诺有人接案、代付报酬或自动解决争议。
