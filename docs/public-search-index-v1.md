# 公开搜索索引与后台重建 v1

2026-09-10，C11-06。Schema 32 在现有 PostgreSQL 中加入公开候选索引，复用已有 `jobs` 表、租约和 Worker 进程。动态云服务尚未部署。

2026-09-10 后续：Schema33 扩展 Worker/Hub 来源和触发器，保持两张索引表及原有开关；详见 [建设者来源搜索](builder-source-search-v1.md)。

## 索引边界

新增 `search_documents` 和 `search_index_control`，共两张表。文档按 `case / history / proof / capsule / worker / hub` 保留来源 ID、所属主体、公开标题/摘要、来源版本、最小元数据、依赖引用、构建时间和有效期限。私有 Case 正文、私有配置、Context 材料、凭据和签名密钥不写入索引。

数据库提供来源/主体 B-tree、依赖引用 GIN 和 PostgreSQL 原生 `tsvector` GIN 索引。首期 API 保留已有子串匹配语义；`tsvector` 可用于明确的词项查询，尚未以全文分词替代既有匹配规则，没有引入向量检索或独立搜索引擎。

公开 Case/History 只有在其来源事件均允许匿名公开读取时进入索引。公开 Proof 可引用私有 Case，索引只取显式公开的 CI 来源字段；Capsule 只取公开版本的标题、问题模式和能力声明。Worker 复用当前 Evidence/Proof 来源校验，不加载签名服务或身份/session 实现；签名核验继续由提供结果的 API 执行。

## 查询与失效

- 启用后，匿名 `/v1/search/query` 从索引取得最多 200 个候选，然后调用原 History、Proof、Capsule 或 Builder 服务再次读取当前可见结果。候选表不能授权读取；即使候选内容陈旧或错误，也不能返回私有来源。
- 有会话的查询和既有履历接口继续使用实时授权视图；Case/History/Proof/Capsule 可包含用户获准读取的私有记录，Worker/Hub 统一搜索仍只返回公共元数据。私有内容不加入匿名索引。
- Case、Proof、Capsule、Builder、Evidence、验证任务、Consent 和 binding 的相关变化通过数据库触发器移除已有候选并安排重建。源数据更改和候选失效在同一事务提交。
- 来源更新会替换该来源队列记录的代次和租约；旧 Worker 提交必须仍持有当前有效租约。读取来源与 Consent 使用现有锁和受限辅助函数，撤销不能在构建过程中被旧记录覆盖。
- 文档有效期最多 60 秒，遇到更早的授权/Proof 到期则缩短。读取时检查有效期和构建年龄；后台落后时隐藏过期项。页面只报告当前可见结果，不提供全局索引计数。
- 达到候选窗口时仍报告 `windowLimited`。有当前可读游标时继续；没有游标时提示缩小条件。该页不能证明全库不存在匹配。

## 重建、重试与退出

首次扫描每批最多 100 个来源，在控制表持久保存来源类型和 ID 游标；进程重启可续扫。每个来源复用一个 `search-index` 作业，30 秒租约、最多 5 次尝试；临时失败指数退避，耗尽后标记失败。新的来源变更或显式全量重建会重新排队。

Worker 每轮公平处理一个 Evidence 作业和一个索引作业，每秒推进扫描及过期候选刷新；停服和事故暂停同时停止这两类处理。索引作业用固定 JSONL 事件 `search_index_job` 记录结果，运行配置记录索引模式。

物理删除清单包含派生索引和所属索引作业。删除事务抑制本主体再次排队，避免删除触发器重新创建刚清除的后台记录。控制表是服务配置，不属于某一用户；公开候选可由原文重建，不作为新增用户导出原始数据集。现有本人导出集仍为 30 类。

## 启用与 AI Agent 部署说明

1. 按原隔离环境规则配置 PostgreSQL，先运行迁移，再由数据库管理角色应用 `api-role.sql` 与 `worker-role.sql`。API 只新增索引读取权限；Worker 获得派生表维护和受限源锁/入队函数权限，不取得源数据修改或签发权限。
2. Worker 设置 `GALAXY_SEARCH_INDEX_ENABLED=true` 后显式启用并首次重建。新数据库默认不启用，旧查询协议保持可用。设置 `false` 会清空派生文档并关闭索引；重新启用会从头扫描。
3. 未配置该环境变量时，当前 Worker 不处理索引，也不修改数据库已有开关。如果数据库仍开启而 Worker 没有处理，过期项会隐藏；恢复 Worker 或显式关闭索引才恢复相应读取路径。
4. `SearchIndex.configure({enabled:true,rebuild:true})` 是受控维护调用，可请求全量重建。使用已选环境的 Worker 数据库角色，在原工具/维护进程中调用；没有新增公开管理 HTTP 入口。
5. 观察 `search_index_job`、控制表游标、作业状态及公开查询。不要把后台作业总数直接公布为公开记录数；其中可含不具备公开条件的待检查来源。
6. 关闭或回退功能使用 `false`，保留 Schema 32；数据库按既有备份恢复/前向修复流程处理，不自动删除迁移或源数据。

验证范围和源文件摘要登记于项目 `GALAXY_PUBLIC_SEARCH_INDEX_PROGRESS_2026-09-10.json`。实际环境的容量、目标吞吐、多实例调度表现以及真实用户相关性仍需原阶段验收。
