# 社区、发现、画像与推荐

发现覆盖内容、人、项目和机会。临时搜索不自动建立项目、公开请求或长期画像。

## 内容与目录

统一查找覆盖讨论、方法、项目／作品与公开求助，分别给出少量真实可读预览，进入完整目录沿用原词。各类独立加载与重试；也可不填关键词直接浏览方法和项目。项目按实际功能或较大组成部分查找，不仅比较技术栈，用户可重视资源复用或相似的人，复用价值不是推荐前提。

先呈现能提供的帮助、人物或项目概览，再按需展开经历、条件与限制。相同领域仅是线索，不等于当前愿意合作。结构化匹配不冒称模型语义理解。无结果可调整或结束，不做全网无差别广播。当前联系意愿、公开作品和资料可读性分别判断。

## 论坛、发布与收藏

社区以论坛为主，作品、过程与后续更新融入帖子和专题，不重复登记多套成果。普通成员可发起并维护有主题和维护者的长期独立版块，全站分类由运营整理；具体创建维护流程仍需细化，现有主题浏览不证明此能力已经具备。

初始主题为“技术与工具、艺术与创作、阅读与学习、生活与兴趣、银河使用与反馈”，另有全部及旧帖未分类；这是初始组织方式，可按内容分布调整，不是资格或能力等级。旧帖不由程序猜主题。按首次发布时间浏览，编辑版本时间另列，当前主题可搜标题和正文；查询、已加载范围和焦点按[连续操作规则](experience.md#草稿返回与提交)保留。

改写草稿不覆盖已发表版本，旧链接保留对应正文和回复并提示新版。主帖撤回不自动删除他人的独立回复，只保必要定位。帖子详情以正文和回复为主，提醒直达上下文，编辑、关注、举报和删除就近可达。

创作者可选公开、银河账户、指定等级／荣誉或特定专业条件等受众，阅读与参与可按用途分别控制。具体默认、门槛和组合仍待细化，不形成统一升级路线。主帖扩大受众不顺带公开引用、附件和他人回复；受众条件只执行访问资格，遵守[平台判断边界](overview.md#人模型与系统)。

帖子、方法、项目和人物均可私人收藏，按种类回找，稍后阅读无需填写工作目的或开启关注。方法收藏保留准确版本，收藏只存引用，取消即移出当前列表；引用正文按[保存与失效](data-and-files.md#保存与失效)读取。

## 画像的用途与取材

后台需要事实画像、可解释的兴趣／阶段／变化、人工纠正及参与下降／潜在需求预测，并跟踪预测与实际表现。事实、推断和预测分开，一次搜索或点击不直接变成确定长期兴趣，样本不足不编造概率。计算与语义分析采用[后台共同分工](admin-automation.md#策略生效与执行)。

| 来源 | 允许用途与边界 |
|---|---|
| 正常站内曝光、浏览、搜索、点击、收藏、公开参与 | 按社区分析、兴趣／需求及推荐用途集中组织，不逐项重复确认；保留来源、时效与纠正 |
| 本人在银河的公开帖子／回复 | 可形成有来源且可纠正的推断，与自填事实分开；具体字段、期限及来源变化处理依完整数据合同 |
| 私聊正文及反映正文的摘要／特征 | 排除兴趣／需求画像、预测训练和个性化推荐，不借共享记忆或子助手转用 |
| 举报、申诉、治理取证等专门材料 | 留在原处理复核用途，不转为画像和推荐；跨模块获准治理／安全分析另行保留 |
| 公告和系统邮件 | 作为系统通知，其标题、正文、目标、阅读／点击／退信及派生特征排除画像、预测和推荐；必要业务与运行记录保留 |
| 本机反馈、未上传资料、站外资料或归属不清旧记录 | 不能因网站统一后台而自动上传或归到所有关联账户 |

通知链接进入普通公开帖子后的独立浏览与参与仍按正常社区用途处理，不能把这份许可反推为邮件打开或点击可用于画像。反馈收集等专门正文同样留在其任务用途，不因跨模块分析成为兴趣来源。

官方站内信同样按通知用途隔离属于一致性设计建议，并非用户对该渠道另作一次独立选择。私聊次数等非正文统计不能从上述正常数据范围自动推定获准。推荐组件只接用途所需标识、标签与反馈，不复制邮箱、全账户资料和案件全文。匿名关联须实际证据，不凭 IP 或同设备合并不同账户。

账户画像常规页只显示分析汇总、简洁来源类型／时效及纠正，推荐仅列类目摘要，不展开具体文章和逐条行为，不另放推荐内容关联。内部仍保留必要来源关系。前台只提供推荐原因、不感兴趣、最新／非个性化浏览，不增加本人兴趣管理或推断标签编辑页；后台纠正继续保留。

## 推荐运营

目标是当前需求匹配与发现新主题、新内容、新作者之间保持平衡，具体比例和权重不是用户既定参数。实际推荐由程序和专用服务选择，日常运营不逐篇挑选、排序或批准文章。后台关注整体表现、主题供需、曝光集中、调控方向、生效与异常，必要时进入原内容查异常。

按已有分类／标签加跨分类需求主题表达需求，不另造前台分类，不默许 AI 增删正式体系。可常规增加或减少展示机会，控制重复和过度集中，保留个人需求、供给、负反馈及上下文，不向所有人强推同一配比。关键词不简单等于字面包含，调控减权不等于治理下架，推荐候选不直接成为置顶或精选决定。

Gorse 负责候选与排序，银河检查当前内容资格、混合去重、有限补取及回退；OpenPanel 汇总正常使用事实，Agno 按用途辅助复杂分析。只把真实可见展示计为曝光，不能把返回候选当用户已看见，点击不等于需求满足。按真实请求、内容版本、位置和策略归因，前后变化不冒称因果效果。无权限、未知、真零、无样本各自表达。

预测影响用户主动使用时的推荐并供后台建议，不因流失或需求预测自动发送主动站内信／邮件。原获准事件、周期计划与结果通知保持，但不能用 AI 策略把预测串成新发送用途。统计报表导出、正式同期随机 A/B 不纳入本轮产品。预测项目定义、训练条件、期限、权重和评价参数仍需具体设计；scikit-learn、Recommenders、Unomi 等研究不等于已采用组件。

## 搜索运营

搜索运营保留搜索词、无结果、点击及后续使用分析，同义词、排序、生效版本、变更与恢复；AI 按需分析检索问题与内容缺口。后续选择取消搜索预览模块，仅保留程序固定的当前可见资格过滤，不增加运营主动按分类／标签排除。它与推荐的主题加减权、治理下架是不同能力，不因早期综合候选提及预览和排除而重新纳入。
