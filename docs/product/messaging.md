# 官方公告、站内信与系统邮件

官方信息明确分为公告、站内信、系统邮件。公告可供未登录访客阅读，不扩张为资讯、专题或活动运营体系；站内信进入账户消息；系统邮件走实际邮件渠道。网站邮件管理覆盖发信身份、连接、模板、队列、测试和退信，不建设收信工作台。

## 内容、受众与计划

支持全体、指定账户、组织账户及按已有属性筛选，组织账户本身作为接收者。提供模板、定时／周期计划、网站支持的业务事件触发、启停、执行记录及逐收件人结果；不建设常用人群库，本轮不新增接收偏好、退订或停止投递名单。

条件式计划每次发生时按当时条件计算并冻结本次账户清单，新符合者可进入下次，不能在本次分页中继续增加。指定 UID 保留准确范围；发送前仍检查当前对象与渠道资格，通用版本和授权衔接见[策略生效与执行](admin-automation.md#策略生效与执行)。

账户目录不可用是失败或暂停，不能按空名单成功结束。系统邮件投向账户有权使用的已验证邮箱；组织没有合法邮箱时记录不可投递，不改投成员或负责人，共用邮箱也不直接合并业务账户。公开公告没有访客收件名单，私密举报结果不能改作公开公告；站内信与私聊分别存储判权。已发送邮件需更正时形成可追查的新通知，不悄悄改旧发送记录，重要批准绑定准确版本和范围。

按[后台分工](admin-automation.md#策略生效与执行)，固定模板、受众计算和投递使用程序，普通新文案或复杂方案才按需 AI。普通公告和主动群发可在已批准用途、事实、内容和受众内自动发布。消息的必须人工类别包括站规／权责／数据使用规则正式变更、重大故障或安全事件对外说明、事实待核实或争议。认证邮件与内部运行告警继续各自原流程，不能由消息策略改认证规则。

消息数据的画像准入与预测触达边界统一见[画像取材](discovery-and-recommendation.md#画像的用途与取材)和[推荐运营](discovery-and-recommendation.md#推荐运营)。

## 发件身份与品牌

统一 AGI Galaxy 品牌，五类公开身份如下：

| 用途 | 发件地址 |
|---|---|
| 账户、验证码与密码重置 | account@agigalaxy.org |
| 系统通知 | notice@agigalaxy.org |
| 社区消息 | community@agigalaxy.org |
| 更新信息 | updates@agigalaxy.org |
| 团队联系 | team@agigalaxy.org |

Reply-To 统一 team，仅 team 正常收信。采用“清晰标准整体＋居中官方落款”：共用原轨道 Logo 和排版，正文与操作之后放系统勿回复及团队联系，最末居中官方导航和当年版权。验证码及防误用提示属于对应正文，不塞进所有邮件的公共头尾。具体投递服务商、DNS、连接及送达证据属于部署配置，不从品牌要求推导必须无中继直投。

五类显示名分别采用“AGI Galaxy 账户／通知／社区／更新／团队”。前四类不增加接收别名、全收或转发，正常回复与供应商信封退信分开。供应商可能自动加入退订头或实施抑制，“银河不新增退订产品”不能写成供应商没有退订／停止投递，也不能靠伪造无效链接或清除拒收绕过；认证及重要通知的实际投递影响由服务配置核实，未选择三供应商自动切换。

## 配置与投递状态

消息栏目维护内容、受众、计划和投递账本；系统设置的邮件页统一运营消息、注册／密码重置及运行告警的连接，可共用或分别指定，显示各用途实际生效结果。连接、身份和测试仅维护一套真源，旧 SMTP 路径兼容直达不另造表单。发件身份、Reply-To、模板和认证流程保持各自合同，不因换连接扩大权限。

配置保存、测试、实际采用及凭据保护沿[系统设置规则](admin.md#规则审计设置与维护)。邮件页须区分原有观察来源与已由新配置采用的来源，测试邮件不能制造真实业务事件。

复用银河通知、权限、PostgreSQL／pg-boss 与 Nodemailer，按需模板组件；Novu、listmonk 等研究不等于采用整套平台。延迟发送保留原批准来源，不能因异步执行把 AI 伪装成人员。

队列接受、SMTP 接受、最终送达、退信和未知分别记录；提交恢复按[通用操作规则](experience.md#草稿返回与提交)。邮件外部副作用不能靠数据库回滚撤回，重试绑定原身份、收件人和内容；不能用一项“测试成功”概括全部认证、运营和告警渠道均已验收。
