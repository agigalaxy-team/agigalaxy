# 产品范围与职责

银河让人以较低门槛在自己的事情中取得帮助、找到相关的人与工具、交流、协作并复用经验。用户可以只阅读、闲聊、展示作品或使用一次方法，也可以发布请求、参与项目和长期社区；这些用途各自成立，不要求完成一条统一的贡献流程。

长期方向是面向更多人群和领域的 GitHub 式协作网络，强调开放协作与知识平权。具体开发者试点不缩小产品面向全领域的范围。官网、社区、客户端和 AI 接入是不同入口。

## 五层职责

| 层 | 提供什么 | 产品边界 |
|---|---|---|
| 获取信息 | 在原环境取得获准目标、尝试、环境及材料 | 不默认上传整个会话、仓库或工作区 |
| 组织帮助 | 自己的 AI、方法、人、团队、工具和服务 | 真实参与者决定如何合作，执行发生在实际环境 |
| 产生事实 | 实际尝试、介入、输出、依据、核查和解决情况 | 不用接单、点击或模型自评补造成功 |
| 核心积累 | 稳定主体、声明、履历、外部认证、有限荣誉及方法 | 声明与事实分开，保留出具者、来源与范围 |
| 信息服务 | 发现、查询、比较、机会和变化 | 使用当前许可，可由官方或第三方提供 |

五层是职责划分，不要求五套服务、五张页面或用户逐层操作。具体工作对象及其产生条件见[请求与协作](collaboration.md)，界面不由数据库字段反推流程。

## 人、模型与系统

用户表达目标、决定自己的资料范围及对外行动，并判断帮助是否适用。自己的模型理解问题、整理获准信息、比较方法、准备内容，在有效授权内执行。普通阅读、发帖和聊天保留手工路径；模型接入不是前提，也不按固定失败次数强制启动银河。

银河提供可靠的数据、通信、发现、权限和执行服务，程序处理版本、去重、签名、状态与恢复。后台运营 AI 是独立的管理能力，其身份、模型与执行分工见[后台规则](admin.md)及[自动运行合同](admin-automation.md)。

银河不进行可信度判断或能力预估。它提供获准依据、认证信息、历史与来源，查阅者或自己的 Agent 自行判断。验签、完整性、访问检查只说明所检查的事项；不转换成可信度、证据强弱、可靠性或全局能力排名。缺少银河履历不等于缺少能力。官方不提供现实主体或专业资格认证，只接入和展示外部出具者的认证。

## 开放生态与长期参与

官方服务是可选参考入口。第三方 Hub 可按行业、组织和社区经营自己的服务；Bridge 保留外部观察的来源与限制，Worker 在参与者或获准环境执行。互联不强制把私人任务、聊天或执行权交给官方，协议和能力声明只能说明实际支持范围。

有用回复、一次参与和方法借鉴先提供价值。高质量积累依赖真实来源、条件、结果、复用反馈与纠正，不能用安装量、导入量、发帖量或模型摘要量替代。社区乐趣、身份认同、荣誉、头衔、积分和等级是长期参与方向；有限 Honor 不等于完整激励制度、专业认证或额度层。

核心贡献者共治、非营利基金会或开源社区理事会、官方可持续服务支持公共组织并资助开源生态，属于待细化方向。组织形式、章程、预算、监督、具体激励和分成尚未决定；“灵魂节点”不产生协议特权。资源密集的完整会话私有云保存可考虑增值服务，价格、免费额度、套餐和退出条件未定。不据此承诺固定收益、无限保管或已经成立公共组织。

本人资料的纠正、删除、申诉、导出与必要退出不以付费为前提。停止新增上传、继续保管既有资料及取回资料分别说明实际服务条件；资源不足时先控制新增负载，保留允许的读取、导出和退出。
