# 运营后台、权限与治理

后台覆盖网站运营、治理、官方消息、分析、业务设置与统一维护。跨业务的程序、AI 和人工分工统一见[策略生效与执行](admin-automation.md#策略生效与执行)；本页规定各业务的角色与具体处置边界，不能由“管理员”或“AI”泛称推定权限。

## 工作区域与设计

采用工作台加业务领域分组：用户与账户、社区治理、内容与发现、公告与消息、数据分析、策略与 AI、权限与审计、系统设置、系统维护。权限与审计独立一级，运行监控与故障日志留系统维护。后台面向桌面，不增加手机专用布局。

工作台包含仪表、AI 处理日志、沟通、状态、预设查询、最近事项、旁置待办与可自定义常用入口。AI 沟通集中在此，切换领域 AI，业务详情只关联确有任务，不再加聊天入口。待办按类型、状态、时间进入原对象，包含待审、举报申诉、反馈、文件／发送／备份异常和待人工决定，不增加认领、指派或催办。完整自动运行页组织计划、健康、效果、用量和异常；AI 工作账户提供岗位概览、角色权限、值守要求和变更。

已选择的页面保留有效信息组织：用户目录宽表加右速览；账户概览采用人物卡和组织化详情，画像只展示汇总；公开内容及私聊审查以内容和案件上下文为主；文件左宽列表、右详情与记录；角色左列表、紧凑权限表、下方变更；推荐主题供需主区、右侧调控；系统设置固定四页签、宽幅双栏。管理账户上全宽表、下角色权限；AI 工作账户上五岗位表、下授权区。其余具体比例、样例数字、示例角色和字段不因图稿被批准；同对象页签和基础状态共用组件，避免重复信息。

## 用户、管理人员与 AI 身份

用户账户、管理账户、AI 工作账户分别管理。用户目录查全部注册用户，提供高量查询、筛选、分页、密码重置链接、停用／恢复登录、撤销会话和有记录的资料纠正；邮箱改变仍须验证，原业务参与限制独立。组织账户纳入同一目录，不新建成员、负责人、邀请或退出体系。

管理身份独立于普通账户，不公开注册。唯一根在启动前预配置，绑定不可变管理 ID，邮箱变化不迁移权限；根不可由页面注册、新增、删除、停用或普通人员更改，只有根能提升或撤销其他管理员资格。管理账户新建、禁用、删除及维护由根或已提升管理员在相应操作权限下办理；普通人员即使误得维护权限码也不能绕过资格。目录读取仍依读取权；本设计不另建“只能维护比自己权限少的人”的等级体系。新建临时密码首次强改。管理邮箱可选，未填写不应被资料补全阻断；填写及更换要验证，更换验证成功前保留原邮箱，提交验证邮件不表示送达或已变更。

业务角色按功能与操作配置并分配给人员或 AI，可撤回并留历史；不增加按具体版块／分类划人员授权。公开读取、下架、私聊正文、发消息、配置、角色分配及敏感审计读取分别验权。常用固定模板或复制已有角色仅填可编辑草稿，保存并分配才生效，不建独立模板库，模板不扩张到未来新权限。

五个稳定 AI 岗位对应总控、治理、消息、数据与发现、运维，初始无角色即无业务摘要、查询、材料读取、可执行卡或执行权限。人员可用哪些 AI 由业务角色分配，普通人员可限制，根始终全权；受托业务查询及操作卡取当前人员与所选 AI 的权限交集。岗位名称或领域不是隐藏权限，新增权限目录不自动给旧角色加权。外部服务／Agent 代行管理员权限的 API 凭据模块保持设计搁置，内部接口和站内工作台不因此停用。长期自动授权、身份执行依据与总控委派见[自动运行](admin-automation.md#工作台与稳定-ai-账户)。

## 治理对象与自动范围

| 对象 | 获准自动范围 | 保留的人工与恢复边界 |
|---|---|---|
| 公开帖子／回复 | 分级待审判定、单条下架及恢复原自动下架；授权范围和数量／影响上限内批量下架、恢复 | 预览、理由、逐项结果；无法判定、超范围或触停止条件转人工；不扩成批量账户／文件／项目治理 |
| 私聊单条消息 | 线索触发后获准屏蔽及恢复原自动屏蔽 | 只影响后续服务端展示读取，已送达副本不追回；恢复不绕过撤回、到期或权限 |
| 单账户短期参与 | 明确防刷规则或获准语义判断设置短期限制、提前解除原自动限制 | 长期停用人工决定；具体单次／累计时长与条件另定，不扩为认证或批量处置 |
| 单项目／协作对象 | 违规暂停及恢复原自动暂停 | 官方不参与日常项目经营或分配任务；范围及暂停影响按具体合同 |
| 单文件 | 可恢复隔离、停止访问及恢复原自动隔离 | 检查扫描、当前状态和权限；不授予永久删除、任意批量治理 |
| 公开内容编排 | 在授权范围归类、调整已有标签、适用置顶／精选 | 不改正文、不自行增删分类／标签体系；推荐不等于编排决定 |

正常用户即时发公开内容，新用户初次及命中规则进入待审；待审可在授权内由规则／AI判定。私聊即时发送、事后审查。所有复核先检查重要事件、未覆盖异常和人工接管；普通原自动处置可自动维持或纠正，原人工处置由人工决定复核结论。人工批准后代码执行仍记录人工决定来源，不能记作 AI 自主纠错。

私聊 AI 取材由举报、申诉或明确防刷／垃圾线索触发，先用元数据与规则，确需理解再交必要正文，不常态巡查无关聊天。可在事先批准的关联账号、时间、数量及累计范围内扩查必要片段，超范围转人工，不能任意遍历。允许符合后续核查条件的外部模型或自部署模型；这不等于批准任一供应商、字段或实际传输。告知、读取者及具体取材范围仍须落实，回退调用也受同一范围限制；证据留存在[数据规则](data-and-files.md#保存与失效)，跨用途限制在[画像取材](discovery-and-recommendation.md#画像的用途与取材)。

旧到期／无引用文件清理每次先列具体对象、原因和影响，由人工确认本次计划，再由代码复核引用、留存与资格逐项执行；新对象或实质范围变化须重新确认，一次批准不是周期授权。新中转缓存的自动到期清除另依[文件规则](data-and-files.md)，两者不能混用。

## 规则、审计、设置与维护

业务规则管理审核、防滥用、参与额度／频率、功能启停、生效版本、变更与恢复。规则样本测试可输入文字或链接看命中与预期动作，不产生正式处置；拦截关键词、域名和规则例外集中维护并留原因。共享 IP 不等于同一人，内部 new／normal 额度层不等于能力或激励等级。

规则使用常用表单和可理解的组合条件，显示用途、对象、条件、动作及版本，不提供任意代码执行入口。例外只覆盖获准的特定规则，不绕过私聊用途、访问、人工恢复或清理批准。功能启停分别说明新增操作、在办事项与既有展示的影响，不混同事故维护或服务启停。发布后以真实消费者采用为生效依据，冲突或未知不能冒充未命中；恢复旧配置也是可追溯发布，不自动撤销既有业务副作用。

公开内容目录可保有当前合法的最小编号、状态、版本、时间及独立运营历史，但不可读正文、标题、作者和原分类不从旧缓存恢复，不可读对象不能加入处置。统计区分公开、下架和不可读；有界统计无法覆盖全量时显示未知，不把截断数据当总数。

业务审计区分发起人、决定主体、执行账户、对象、依据、版本、前后状态和真实结果；敏感材料读取单独验权，不能靠看审计列表取得正文。安全模块集中现有记录、关联追查并 AI 辅助分析，不新增专门异常识别、主动安全告警或安全事件状态体系，既有运行告警继续。

使用反馈只收集问题／建议、分类和处理状态，不增加用户与运营往返沟通或用户侧进度查询；举报与申诉则反馈实际处理进展及结果。

系统设置仅常规、邮件服务、服务接入、高级四类，模型、业务规则、额度和数据策略留原业务栏目。接入优先分析、推荐、搜索、AI 执行和文件扫描，支持地址、受保护凭据及必要参数的保存、测试、应用与真实结果；登录服务器、数据库、域名和证书留维护工具。同一配置只有一个编辑真源。保存、测试通过与实际采用分别表达，凭据只留受保护存储，页面和审计不留原值。

官网一般固定，CMS 页面、图片、站点编辑及官网发布退出日常主导航，不能因既有实现恢复一套内容管理菜单；已有内容、历史、兼容直达与发布能力不据此删除。图标与名称等范围不等于所有更换能力均已实现。

整站备份优先原生在线与有限写入协调。每次生产恢复须人工确认恢复点、影响、可能损失和验证／开放条件，代码统一执行；失败或需改方案转人工，不逐组件或逐步骤新增审批。恢复不以 AI 沟通或模型结论为前置，模型不可用时仍能由人工批准启动。计划内业务、搜索、推荐、分析、AI 等全部满足条件后统一开放，不采用核心先开。业务内容、文件及引擎按获批恢复点处理，账户、密码、权限和密钥保持当前安全权威，不复活旧密码、撤权或旧密钥；过期与删除状态仍按所属数据政策核查。离机位置、频率、容量及恢复目标须按实际方案确认。
