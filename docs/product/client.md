# 客户端、宿主与本地工作积累

客户端由统一 Go Native 核心按[用户侧模型职责](overview.md#人模型与系统)接入已有 AI 工作环境。MCP 提供完整能力，Skill 说明用法，当前 Agent 选择如何工作；宿主插件负责各自 SDK、事件与界面适配。命令行、小面板和菜单按实际宿主支持使用，不是 Agent 调用能力的前置流程。

## 初始化与连接

需要本机身份时先发现适用的[既有身份](identity.md#身份连续性与关联)，没有时再创建，可跳过官方账户注册和关联，以本地身份和履历开始使用。工具支持的公开阅读不要求先创建身份；需要本人权限的线上操作再连接所选官方或第三方 Hub，上传范围沿[数据规则](data-and-files.md#本地工作资料上传)办理。

客户端走银河 HTTPS 接口；Keycloak、Prosody/XMPP、数据库、存储及扫描器由 Hub 或官方运营者维护，不是普通客户端前置。具体运行时和宿主支持以发行说明为准，不能把单一宿主覆盖推成全宿主支持或完整离线安装。

### 通用插件的运行方式

通用插件按需启动，启动后在本次系统登录期间保持运行；关闭某个 Agent 不关闭通用插件，用户可主动退出。多个宿主及官网接续共用其本机身份、资料和处理状态，仍保留不同身份、服务及任务的原有归属。此决定不包含开机自动启动或自动变更系统启动设置。

首次接入只配置当前宿主的当前系统用户范围，使该宿主的不同项目可使用；不同时修改其他已发现宿主。以后从另一宿主使用时，再将其接入同一份核心。接入同一资料范围时沿用原配置与身份；同一核心仍可隔离持有不同资料范围及服务，接入新宿主不重新创建身份。

统一 Go 核心支持 npm 引导、原生整版包和适用容器交付，由 Skill 配合当前 Agent 发现环境、复用已有安装、选择方式并处理故障。JavaScript／TypeScript 保留引导、宿主 SDK 和界面职责；交付方式不另建业务核心或身份。程序负责可靠的发现、安装和维护动作，Agent结合实际失败调整方案；已有安装优先复用，不因换入口而重复创建身份或独立资料。宿主配置、网络或模型故障分别处理，不把修复等同于重装、重置或扩大授权。

保持连接本身不调用模型。程序可以接收变化、保存结果和等待接续；需要 AI 判断时，仍使用已配置的用户侧执行环境。宿主是否支持后台执行须分别接通；没有可用执行环境的工作保留待接续状态，不能因本机服务存活就显示为 AI 正在处理。

用户明确作出的新持续处理委托沿用当前Agent已有的工作区工具和权限，不再增加独立工具开关；按交代的任务处理，房间读取、起草和回复仍分别遵守银河原授权，需要新的业务授权时沿原流程。以前仅分析的关注不自动扩大；网页接续通过MCP读取原工作资料，由当前Agent继续处理。

当前机制、接线范围与宿主差异集中在[Native工程](../technical/native-client.md#通用插件与共用本机服务)。身份恢复、普通工作积累、模型整理、原件与同步、求助协作、持续参与、Worker及发行均在范围内，不以安装成功代替这些能力完成。

## 普通真实工作的默认本地积累

初始化协议说明默认记录内容、用途和本地保存方式。客户端取得的普通真实经历默认积累到本地 ID，即使未查询银河、未向外求助、没有工具调用也可记录；不要求先开菜单、建 Task 或逐项确认。写作、研究、学习和讨论保留工作价值。该记录不等于持续模型关注、默认复制完整会话、上传或网络事实发表。

程序保存实际取得的观察、来源、处理位置及环境版本；当前Agent按任务自行选择工具、分批与整理时机，用自己的模型整理工作目标、尝试、修订和可读摘要。用户消息、AI 可见回复、工具实际结果与产物引用分别归属，多轮可归并同一工作，但不改写原行为者与历史；结果含义统一按[工作事实](collaboration.md#事实结果与经历)解释。

下表说明职责，不要求 Agent 按时机逐项执行固定流程。

| 时机 | 程序职责 | 模型边界 |
|---|---|---|
| 激活或重连 | 接续身份、上下文与处理位置 | 不为初始化单独调用模型 |
| 新消息、回合或工具完成 | 保存关联、真实状态和新增范围 | 自然阶段整理，不逐流式片段调用 |
| 空闲或阶段收束 | 合并新增、标记未覆盖部分 | 支持的宿主可用用户已选模型整理实质增量；其他宿主在下一正常回合接续。没有新增内容不启动整理 |
| 主要环境变化 | 读取、比较并形成版本 | 不猜安装状态、不预估能力变化 |
| 停用或中断恢复 | 保存位置、补取、去重 | 不强行关机总结、不补造遗漏经历 |

有事件接口优先接事件，有正式查询接口则补取获准材料，仅 Skill＋MCP 可由宿主模型提交结构化记录；无读取或执行能力时说明具体限制，不扫描无关历史。房间 Watch 不等于观察宿主前台会话。模型暂不可用仍保存可观察事实，以后只整理未覆盖部分，不由官方模型补做；网页链接与MCP读取见[AI 接续](experience.md#网页与自己的-ai-接续)。

用户已选择支持宿主的阶段自动整理：正常工作可按需要使用银河帮助，无需先明确提及银河；私有工作摘要和适用经验可在后续工作中检索、读取与修订，不要求先形成线上任务或正式 Capsule。已处理位置与摘要覆盖分开，无新增方法可以保持不变。能力接线与宿主实际覆盖集中见[经验复用方案](../technical/native-learning-plan.md)和当前工作状态，不能据此推定所有宿主均已接通。

结构化观察、工作摘要和原件引用或获准副本分开管理。Agent 提交已读范围的摘要，程序自动关联该覆盖范围内的全部真实观察，也可合并 Agent 补充的同一工作更早来源；不要求手工列全观察编号。摘要保留覆盖位置及修订，新到材料继续待整理，不伪造房间 ID；宿主原件消失且无副本时说明不能回查，不因来源链接存在承诺永久恢复。具体保存范围、期限、批次和存储组织由实现合同定义，不堆成无限增长状态。

## 环境版本、摘要与关注

客户端读取主要环境事实并比较变化，工作引用当时观察到的版本，ID 保持稳定。下一次选择的模型与回合实际用的模型分别记录，未知保持未知，晚发现只记观察时间，不倒填精确切换时刻。版本归因不解释能力增强或减弱。

个人摘要默认本地，可手工整理或用自己的模型，可选同步本人私有空间；生成不自动发房间，同步不等于分享。完整会话归档是另一项范围，见[数据规则](data-and-files.md)。持续关注需实际选择范围、期限及停止方式，事件优先、回退轮询由程序处理；没变化不调用模型、不发空报告。普通打开网页和聊天不默认启动监控，关闭后不周期催开，宿主不可运行时说明实际状态。

本人选择与推荐引用可保存在用户端以继续工作，无需手工维护“快照”；若另选云同步，不随个人摘要开关自动开启。获准历史分页连续读取全部允许范围，不逐页重新确认；AI 可参与普通主聊天，不强制设 AI 子区或主响应者，程序继续去重和防循环。

AI 参与设置在同一表单说明当前对话、自己的客户端、允许行为与期限，调整默认保留原到期时间，已停止范围留历史。授权只说明允许行为，不证明宿主仍在运行；个人摘要、重点与备注留原对话，不能因简化账户中心另造一份重复管理目录。

## 建设者、Worker 与专业流程

工具页先说明用途、条件及在自己环境的使用方式，再关联真实尝试和结果。配置突出已知环境与限制，缺项保持未知。专业操作可登记 Agent、外部来源适配、社区、Worker Pack、范围报告和维护公告；分组表单复用已有资料，JSON 导入可选，不要求手填内部关系。

Worker 节点身份由节点运营者提供，无目录时不冒用项目作者。Pack 只在 Worker 项目编辑和读取，保留来源、版本、许可、依赖与权限；安装不自动接单或持续监控。仅实际配置的非作者评估者可提交独立范围报告，作者登记与独立验证分开。未测试明确显示未测试，日期保留原精度，哈希和版本不得生成替代值；节点声明、本人报告、CI 来源与原工作结果分别表达。

支持范围在草稿期间变化时，除[通用草稿规则](experience.md#草稿返回与提交)外，还保留不再匹配的旧检查说明，供作者判断如何修订报告。
