# 数据保留说明与技术建议 v0.1

2026-09-11：回应用户“数据保留是指用户履历还是什么”。本文件是待讨论的技术建议，未批准任何新的删除期限，也不改变现有程序或备份调度。

数据保留是服务器存下来的各类数据保存多久、到期后怎样处理。用户履历只是其中一类。授权有效期决定别人现在能否读取；保留期决定数据何时从存储中清理，两者需要分别设置。

|类别|具体内容|建议方向（尚未确认）|
|---|---|---|
|用户履历与业务事实|Case、尝试、结果、Evidence、Proof及履历投影|以持续积累为目的；允许撤销展示、纠正和本人删除申请，不按统一短期限清空|
|选定协作材料|用户明确选择提交的文本和工件信息|按用途和必要性单独设期限；不自动收集整个项目或聊天上下文|
|授权与审计|绑定、Consent、访问和删除处理记录|失效后不能继续使用；可保留的最小审计信息和期限另定|
|临时认证与下载|挑战、临时会话、导出票据|沿用已有到期规则；到期不能继续使用，物理清理规则与业务履历分开|
|运行日志|错误、请求统计、资源用量|采用有限保留窗口；具体天数待定，不保存业务正文或凭据|
|备份副本|用于故障恢复的数据库和文件副本|沿用当前配置，生产保留期限另定；本批不扩展备份工作|

例如，用户撤销一条履历的公开授权后，后续授权读取应停止；这并不表示原Case、证据和审计记录同时物理删除。导出票据到期也不表示被导出的履历到期。已经被接收方下载的副本不受本服务直接控制。

建议先按“业务履历长期积累、临时数据短期有效、运行日志有限保留”区分，再确定各类期限。这里的长期不是已批准永久保存；短期也不是一个自动适用于所有数据的数字。正式期限、删除请求处理责任和当前未开放的联系渠道仍分开登记。
