# 官网账户参与与内容附件

官网普通参与使用真实线上账户 Cookie。银河 ID 由本机客户端插件创建，承担本地身份、履历和获准客户端操作；网页登录不创建 ID。账户可以直接交流和收藏，未登录仅展示登录、注册及回到原内容的路径。

## 账户和本机接续

Web 共用一个账户会话模型组织概览、我的帖子、收藏、设置和本机银河。Native 签名接续是独立的具体动作，不能被 Cookie 登录代替。废弃的浏览器创建 ID 不再从旧 `active`、设备材料或连接偏好恢复；网页恢复码和手工旧设备申请入口已经退出。旧资料不会自动转属账户。本机签名、实际设备授权和当前控制链成立时，网页才使用相应接续设备。

账户聊天使用独立的 `account:<UUID>` 参与引用，记录在 `chat_participants_v3`；不会插入虚构 Galaxy 主体。已有真实 ID 的引用与归属不改写，关联账户不自动取得该 ID 的私聊。Prosody 保留原 GUID JID，账户引用单独映射为 `account-<UUID>`。普通网页只使用当前 Cookie 账户；真实 Native GUID 协议继续核对对应授权。

## 收藏与对话内容

`POST /v1/account/bookmarks/{status,command,query,receipt}` 通过当前 Cookie、准确账户和 CSRF 处理账户收藏。`POST /v2/account-bookmarks/{status,command,query,receipt}` 是获准客户端针对明确账户的代理路径。两者不会认领原 ID 收藏。

收藏仅存来源定位，按社区和私聊回找。帖子、方法、项目、资料及消息每次重新检查源权限；消息隐藏、撤回、到期或退出对话后停止显示受控正文。原操作在发送前保留，回应丢失后查同一回执；切换账户不会继续另一个账户的请求。

摘要、重点和私有备注位于原对话。相关资料及工作提供就近的分享和可携带文件导出；收到的文件可以本地阅读。文件发送发生在帖子或消息中，不另设网盘栏目。

## 帖子及回复附件

`POST /v2/community/attachments/config` 返回实际服务是否配置、文件大小和数量限制。`prepare` 接受附件 ID、文件名、媒体类型、字节数和 SHA-256；`read` 和 `query` 读取当前账户的元数据，`revoke` 撤销本人附件。上传使用 `PUT /v2/community/attachments/<id>/upload`，字节必须与原准备一致。上传结果未知时沿原 ID 查询，在租约允许时重送，不另建附件或延长原到期时间。

实际配置决定大小上限，协议硬上限为 32 MiB，每个内容最多四个附件。文件经存储和扫描后仅 `available` 可进入发布。帖子和回复的原签名载荷只带可选 `attachments: [{id,sha256}]`；元数据另在读取结果中提供。未包含附件的旧载荷不会被默认值重写。发布、附件来源关联、回执及配额处在同一事务中。

下载使用 `POST /v2/community/attachments/<id>/content`，请求必须指定 `{source:{postId,versionId}}` 或 `{source:{replyId}}`。服务检查准确源内容、当前受众、到期及回复父帖；公开内容才允许匿名下载。账户请求失败不会降级成匿名请求。私聊文件不能以附件引用混进帖子。

未发布文件从首次上传起保留七天，已发布文件按准确来源的最晚发布时间保留；撤销、来源撤回或到期进入对象清理。处于清理队列的文件不能再绑定新帖子。元数据不代表对象已删除，清理结果分别记录。聊天与论坛共用实际存储总量、账户容量和并发上传限制。

## AI Agent 部署

从现有服务发行清单、`GALAXY_ENDPOINT`、官方账户配置、允许的网页 Origin、附件配置和 Prosody component 配置发现当前目标，不猜测域名、凭据位置或数据库版本。Cookie 会话、CSRF 和 ID 设备控制属于不同授权依据，不能在失败时互相替代。凭据由进程或既有受保护的服务配置读取，不写进网站、Git、报告或测试夹具。

本批采用追加 schema91：账户参与引用、账户收藏、论坛附件与来源关联；原迁移不改写。先完成本地集中检查和最终制品，再执行既有迁移/角色配置流程。Prosody 模块、API、Worker、Caddy 的精确 PUT 上传及 Cookie 路径和网站应按同一批切换，避免新页面调用尚未部署的协议。Native 旧 GUID 合同仍可用；是否更新 Native 包按实际源码依赖决定。

验证应涵盖无 ID 的真实 Cookie 账户、账号切换、CSRF、源权限撤回、原操作回应丢失、附件扫描与共享配额。对象存储/扫描或传输合同夹具只能证明相应边界，不能作为实际 S3、ClamAV 或 Prosody 验收。浏览器使用任务隔离的无头上下文，生产只核实已有状态和制品，不提交合成账户或帖子。

常见问题包括只隐藏创建按钮却继续加载旧 `active`、把设备授权误当 Native 签名接续、漏部署 `chat_human_message_reads` 账户外键、反向代理遗漏 PUT、私有文件直接公开存储 URL、以账户关联自动取得原 ID 房间，以及未知回应时创建第二个业务操作。这些行为都不属于兼容目标。
