# 客户端发行包与离线消费

2026-09-11当前交付是本地可安装包及已有签名接入流程：`@galaxy/client` 0.1.0，21个入口、63个源码文件、4个固定依赖。新的单次流水线已生成匹配478项当前源码/输入的31项Conformance报告，完成63源码/21入口包的临时签名和独立离线安装；尚无正式生产签名。动态Official/Hub服务未部署，也未发布npm包。当前候选摘要与后续工作见[发行流水线](client-release-pipeline-v1.md)。

## 生成与消费

在已有锁文件依赖的仓库中，用Node≥24.13执行：

```powershell
node scripts/run-conformance.mjs
$env:GALAXY_TEST_NPM_CLI = 'C:/Program Files/nodejs/node_modules/npm/bin/npm-cli.js'
node scripts/test-client-install.mjs outputs/conformance-<本次运行ID>/report.json
```

第二条命令的路径是执行机上npm CLI的示例位置，应先确认实际位置。安装脚本在临时目录中构建允许范围内的客户端，用离线npm ci/pack/install安装并加载全部21个入口，核对包内源码哈希及固定依赖；不会初始化用户身份或连接外部服务。合成 Node 证明测试仅在进程内生成临时密钥，验证完成后删除临时公开夹具。缺少本机npm缓存时失败，不自动切换联网安装。省略报告参数仍可执行安装检查，但不会生成发行签名。

传入报告时，构建源码必须与七项Conformance运行的完整源码指纹一致；构建后的客户端各文件也必须匹配报告。复用jose的JWS/Ed25519签名，绑定包名、版本、文件名、字节数、tarball摘要、入口、准确依赖、锁文件摘要、源码哈希清单摘要、报告摘要、源码和套件摘要、签发者及有效期。发行验证器先核对调用方固定的公钥、签发者和时限，再核对包及报告字节；未知/撤销/过期key和被替换的包或报告失败。

`outputs/client-complete-<时间戳>/`保留tarball、签名、清单、报告、依赖锁、验证记录与临时测试公钥。私钥只在本次进程内生成并使用，不保存。`purpose=local-validation`明确这是临时密钥演练。输出公钥仅供复核该次演练，不能作为正式发行信任来源；本地源码测试报告也不证明第三方独立执行。

## 正式签名接入边界

`scripts/client-release.mjs`的`createClientRelease()`接受已构建目录、对应tarball、报告字节和调用方注入的私钥，返回清单与JWS。`packages/galaxy-official/src/release-artifact.mjs`的`verifyRelease()`接受调用方提供的`trustedKeys`、预期publisher以及包和报告字节。生产调用方负责可信构建目录、打包流程与密钥供应；函数不会自行查找凭据、申请证书或发布包。

信任记录为`{publicKey, notBefore, notAfter, revoked}`，时间单位为Unix秒。发行有效期最长30天，必须位于key有效期内。核验使用本地提供的撤销状态，返回`currentRevocationChecked=false`，不宣称联网获取最新撤销情况。正式签发者、公钥分发/轮换、公开发布目标、目标平台矩阵及评估者授权仍需接入；本批不伪造这些材料。

## 升级与回滚

当前安装包只含63个可达源码文件、包元数据和说明，固定依赖为canonicalize 4.0.0、ipaddr.js 2.5.0、jose 6.2.12、zod 4.5.4。不含宿主私钥、local-host-runtime、数据库或服务端签名模块。安装脚本关闭生命周期脚本；导入模块不会执行身份初始化。

升级先保留当前可用包及其签名、依赖锁和报告，在新目录验证后由宿主明确切换版本；不调用init/reset，不重建Galaxy ID。失败时回到已验证的旧包，保留本地身份和业务日志。本次签名包演练对应Schema18时点源码；后续服务已迁移至Schema20，旧报告不覆盖后续代码。包切换不执行数据库降级。此安装演练未覆盖真实宿主切换或生产回滚。

## AI agent部署说明

先从本机配置发现Node/npm位置和已固定的发行公钥；从明确指定的发行目录读取包、签名和报告。核验实际字节后在隔离目录离线安装，加载全部导出入口并核对源码哈希与依赖，再提交具体宿主切换方案。不得从发行包所附公钥自动建立信任，或把测试公钥当正式公钥。缓存缺失、源码变化、报告不完整、签名到期均应保留原版本，报告具体缺口；不要以重建用户身份处理安装失败。
