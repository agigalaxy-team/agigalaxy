# 履历详情纠正与争议入口

2026-09-10，本地开发，C10-06继续进行中。Schema30/39表，本批无SQL或服务写入语义变更；动态服务未部署。

## 已接通的交互

`/galaxy → 接入银河 → 查询履历 → 条目详情 → 履历后续操作`：

- 本人Case且当前会话具备case-teaser/consent时，可进入“纠正与争议记录”。
- 可选择准确来源事件，追加文字纠正、打开纠正复核、记录争议，或查看已有话题并追加允许的处理状态。
- 关联Assistance且当前会话具备assistance时，可直接打开所选协作；复用既有参与者争议、解决方案确认、举报和处理记录。独立处理者仍受现有moderation角色约束，不因从履历进入而获得新权限。
- 查询反馈和返回列表保留；协作来源超过八项时可分页选择。

所有者复核明确标为 `case-owner-reported`，不是独立裁决。原文本、原结果和原状态变化均保留，新事件追加在原链后。处理状态选项复用现有 `nextCaseReviewStates`，不另造一套状态机。

## 版本、授权和签名

`createCaseReviewFlow` 读取现有CaseClient的本人记录，核对从履历打开时的sourceVersion和目标事件。Case变化、已撤回、目标不存在或非法状态转换会阻止生成可执行预览；不会自动换成新版本覆盖。

正文使用既有revision事件，授权仍是准确 `case.teaser.publish` Consent。编辑默认Private/仅本人，支持明确Public和最多16个私有接收者。**私有revision可能使整条Case退出公开履历**，因为现有History要求整条事件链可读；UI在编辑及完整预览中说明该后果。修改接收者会切回Private，切换Public清除私有接收者。

主控制器排他管理Case复核预览，明确确认后才走现有ConsentClient与CaseClient。可信宿主只对本次正在执行的准确意图读取并使用已有本机密钥；不新建身份、不修改本地Case草稿或绑定状态。发布成功后返回重新查询，显示真实的新来源版本；失败或发送途中取消不自动重发，也不承诺远端已回滚。

菜单回调绑定当前页面代次。旧输入或已取消的确认不能发起新写入；准备/发送期间退出将取消流程并忽略迟到结果。未知结果提示用户重新查询核对。

## 当前边界与下一步

已有Case所有者复核事件会进入History及Proof的伴随上下文。现有Honor源码也读取Case复核和纠正事件计算贡献是否可用；不能据此认为所有Evidence纠正链路已经完整。

C10-06仍缺一般Case的跨参与者申诉/独立裁定（不依赖一个Assistance请求），以及Evidence本身争议和重新验证的完整联动。当前协作独立处理流程不能被描述成所有Case都已有独立裁定。原任务范围、真实来源、真实用户相关性反馈与实际OpenCode人工验收保留。

## 自动化与AI Agent部署

针对性检查覆盖真实本机密钥与服务签名校验、打开→解决→普通纠正、原文保留、私有修订后公共视图变化、版本冲突、所有权拒绝、非法状态转换、准确目标、授权期间取消、原生入口及关联协作处理深链。采用本地HTTP/临时本地数据和宿主接口替身；未安装到用户全局OpenCode。

本批复用既有SQL和API，无需数据库迁移。部署前使用当前宿主和客户端构建，在独立测试Case上打开复核、确认后重查版本与视图；需要其他参与者或独立处理者时走已有协作入口。一般Case的跨参与者处理尚不可用，不能通过手填所有者说明替代独立决定。
