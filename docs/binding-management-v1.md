# 本人安装实例与绑定管理

2026-09-10，C04-09 本地实现，并核对 C04-01、C04-04、C04-10 的既有主体和签名语义。动态服务未部署；实际宿主和真实设备处置仍待复核。

## 身份与来源

|对象|含义与当前实现|
|---|---|
|Galaxy ID / subjectId|本地与远程沿用同一主体 ID；subjects 保存公钥和 genesis proof，不另造能力主体|
|公钥及指纹|genesis 验证 ID 与公钥；回执指纹为公钥 PEM 的 SHA-256，与本机确认的公钥匹配|
|来源|本机 genesis proof 与当前端点签发的绑定回执；来源码和端点报告不等于实名、真实硬件或专业能力|
|installationId|本机声明的软件安装 UUID，不是硬件证明、账户或新的 Galaxy ID；一个实例可以有多份绑定|
|bindingId|该主体在指定端点的一份绑定，关联实例、Scope、期限和撤销状态；凭据与 Consent 引用准确绑定|
|外部 DID、企业身份、Account|沿用既有映射边界，作为独立关联引用；当前绑定不以其替代 Galaxy ID，不虚构未接入的身份提供者或恢复机制|

绑定只证明此次密钥控制权，不自动创建公开 Profile、Case、Proof、Honor、Hub 资格或能力认证。后续业务写入仍须对应 Scope、材料与独立 Consent。[对象映射 v0.3](../../../GALAXY_OBJECT_MAPPING_v0.3.md)继续适用。

## 用户流程

日常“接入银河 → 绑定、审计与数据管理 → 本人设备与绑定”显示安装 ID、绑定 ID、Scope、建立/到期/撤销时间及状态，并标记当前会话绑定。可翻页或筛选某安装实例的全部绑定；本机历史回执和断开本机会话保持原有独立入口。

“预览撤销此绑定”先重新读取目标，再展示准确端点、本人 ID、调用绑定、目标安装与绑定、Scope、期限及影响。输入完整确认文本才使用原撤销 API；不新增密码或另一套签名协议。一次预览只提交一次，取消或换会话后失效。

撤销会阻断目标绑定的全部会话及依赖它的授权；其他绑定保持有效，包括同一安装 ID 下的其他绑定。丢失设备有多份绑定时，按实例筛选后逐份处理，程序不暗中批量撤销。

撤销当前绑定后丢弃对应本机会话；提交结果未知时也不继续使用它。迟到结果不会清除后来建立的新会话。其他绑定的未知结果可重新查询，再决定是否重新预览；没有自动重试，取消不承诺服务器回滚。

## 密钥丢失或泄露

同一 Galaxy ID 的另一有效绑定可撤销丢失设备的绑定。仍持有本地身份私钥时，可明确建立新绑定，但不会自动恢复旧 Consent 或公开资料。

唯一身份私钥丢失时，当前不支持找回原 ID。私钥泄露时，撤销绑定无法阻止持钥者再次绑定；当前不支持保留原 ID 换钥、身份迁移、合并或恢复。应停止继续使用受影响身份并按运营事故流程处置；不提供仅凭邮箱、安装 ID 或旧回执绕过控制权的恢复按钮，新身份不自动继承旧身份事实。

## 接口与兼容

- 新增 `POST /v1/bindings/query`，要求有效 binding scope；输入 `{limit?, after?, installationId?, bindingId?}`，每页1至20项，不接受请求体指定 subjectId。
- 返回 subjectId、currentBindingId、checkedAt、items、nextAfter；只返回绑定元数据，不返回凭据、签名挑战、私钥或公钥正文。
- 先限定本人及当前端点，再按绑定 UUID 升序筛选分页。每页重新检查授权，跨页不是冻结快照；新建绑定后从首页刷新。
- 原 GET `/v1/bindings/{id}` 和 POST `/v1/bindings/{id}/revoke` 保持结构。撤销增加目标端点核对，不能撤销同一 ID 在其他端点的绑定。
- `@galaxy/client/binding-status` 同时导出 createBindingManagementClient，提供 query、prepareRevoke、executeRevoke、cancel；原 createBindingStatusClient 保留。旧端点缺少查询路由时失败，不继续撤销。
- 宿主提供 queryBindings、prepareBindingRevoke、executeBindingRevoke，复用取消和并发状态。构造客户端/宿主不会联网读取绑定或生成身份。
- 停服取回和事故暂停期间允许本人查询及原有撤销操作。撤销审计区分调用安装与目标安装，其他业务开关保持原规则。

原绑定流程仍显示准确 requestJson、端点和 Scope；验证服务签名挑战与本机确认请求一致后，签署准确挑战字符串，回执再核对主体、公钥指纹、安装、受众和期限，会话挑战独立验证。存储公钥冲突不会消耗挑战，并发重复响应仍指向同一份绑定。

## AI Agent部署与验证

无新依赖、表或迁移，当前 Schema39；API角色沿用已有绑定/挑战/凭据读取权限和撤销列权限。更新查询路由、Bindings service/repository、客户端与原生菜单，保持首次初始化冻结流程。测试仅使用临时身份与文件。

专项覆盖真实 HTTP、本机实际签名、多实例并发绑定、同实例多绑定、分页与主体隔离、存储公钥冲突、关联授权失效、其他绑定保留、当前会话退出、取消及旧回调，以及隔离 PostgreSQL 的受限 API 角色。独立客户端封装与正式发行签名/发布分开。

回退代码不需转换已有绑定或草稿，但会失去新查询入口；不能恢复已撤销的权限。生产部署、现实设备识别、运营恢复策略和实际 OpenCode 人工体验仍按原计划验收。
