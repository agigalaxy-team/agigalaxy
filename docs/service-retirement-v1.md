# Official 停服、取回与删除处理 v1（C18-05）

当前Schema26：36表、独立删除账本捕获、隔离重放和迟到审计处理已实现。[删除恢复说明](deletion-recovery-v1.md)。回执最小化、备份到期清理及生产捕获/异地存储配置仍待完成；下方旧批次说明保留其当时范围。

已实现可选停服时间配置、公开状态接口、HTTP阶段限制、下载截止时间、老主体重新绑定及Worker停止领取新证据任务。默认没有停服计划。当前动态Official未部署，本文件和示例都不是已经对用户发布的停服公告。

删除部分已实现签名请求、本人查询/取消、运营审核账本和只读影响预览；详见[删除申请与账本](deletion-requests-v1.md)。主库执行器已接通；生产保留政策和备份删除重放尚未落实，不能将受理、审批、预览或撤销写成“已删除”。

## 时间表与入口

API和Worker通过同一个公开配置文件的绝对路径 `GALAXY_RETIREMENT_FILE` 加载策略。文件在启动时读取；修改后重新启动这两个进程。此文件不包含秘密，其端点必须与 `GALAXY_ENDPOINT` 完全一致。

| 阶段 | 时间 | 可用行为 |
|---|---|---|
| normal | 无计划或公告时间之前 | 原业务 |
| announced | 公告时间起，停止新增业务前 | 原业务；公开停止时间与取回期限 |
| takeout | stopWritesAt起，takeoutUntil之前 | 查询、导出、撤销、老主体认证；停止新主体注册和新增业务 |
| status-only | takeoutUntil起，statusUntil之前 | 公共Proof状态、持钥删除回执及服务/密钥/政策元数据；关闭认证和下载 |
| closed | statusUntil起 | 持钥删除回执和服务及密钥/政策元数据；其余返回410 |

所有截止时刻按Unix秒，采用左闭右开；须满足 `announcedAt <= stopWritesAt < takeoutUntil < statusUntil`。不猜测运营应提前多少天公告、取回多少天或保留多少天。运营填写明确时间后，才形成真实安排。

`GET /v1/service-status` 返回当前阶段、时间配置、运营者、原因、联系入口和删除政策链接；Caddy路由已加入，响应不缓存。健康检查仍独立，ready并不等于接收新增业务。该JSON依靠当前HTTPS端点来源，尚非独立签名的可移植停服公告。

下载窗口内继续使用原认证和当前授权。老主体可以证明同一GUID的持钥权，建立新的绑定和会话取回资料；新主体注册被拒绝，停止前签出的未完成新主体挑战也不能在停止后落地。新绑定不迁移身份、不传送私钥，也不绕过原业务权限。

新增Case、Evidence、Proof、Capsule、建设者事件、Consent、Context授权/接受、治理事件等HTTP写入口停止。已有读取入口和明确撤销入口仍可用；未知新路由不会自动获准。内部管理代码若直接调用业务服务，须自行遵守停服流程；HTTP限制不是数据库全局只读开关。

Worker从takeout起不再领取证据工作，仍清理过期导出票据。切换瞬间已在处理的工作可能完成；应在公告停止时间前后按现有优雅停机机制排空，而不能声称所有在途事务在某一秒同时回滚。

## 取回和撤销

沿用[data-export-v1.md](data-export-v1.md)：默认28类本人记录，另可显式选择六类当前有权视图。原生“导出本人资料”入口照常使用，票据到期时间显示实际截止时间。每张新票据取 `min(600秒、绑定到期、takeoutUntil)`；截止后旧票据也拒绝继续读取，不因重新创建或续会话延长窗口。

先取回并核对文件，再撤销不再需要的Consent、Proof、Context授权及最终绑定。取回时已经失效的他人授权不能复活；本人的历史原始记录仍按本人导出边界提供。下载失败保留未完成标记，不产生“已完整取回”收据。

status-only期间的Proof状态接口复用现有签名、当前授权、来源观察与撤销规则。404可能是未知、私有、撤销、过期或不可查询，不是“仍有效”或“已物理删除”的证明。不能通过停服静态名单曝光此前私有对象。查询服务停止后返回410，历史签名副本不能代替在线有效性检查。

保留公开说明、联系渠道、密钥撤销信息和状态查询服务，需要实际托管安排。进程、数据库或TLS完全停掉后，本实现不能继续应答；最后阶段的静态公告与长期撤销托管仍需单独部署。

## 删除影响预览

在隔离运行环境下调用：

```text
node packages/galaxy-official/scripts/deletion-preview.mjs <GUID> <新的绝对路径receipt.json>
```

数据库配置遵循既有 `GALAXY_ENVIRONMENT` 和 `DATABASE_URL` 规则；使用受限只读/迁移操作环境，不携带签名键。运行本身不代表主体已经申请或同意删除。

预览在只读数据库事务内统计28类本人数据，以及关联的其他作者协作事件、接收材料、Capsule复用及建设者事件。只输出数量和处理事项，不复制业务正文、凭据或他人记录。`physicalDeletionPerformed:false`、`ownershipVerified:false`明确保留，不能将其改成删除成功。

影响清单用于制定实际删除方案，不是全库外键拓扑证明。当前执行器检查完整36表清单、未完成作业、认证材料、治理保留例外、外键及跨作者依赖；不能仅按这些数量级联删除主体。

## 删除请求处理定义

1. **requested**：收取明确的主体/对象范围、幂等请求ID和意图；由当前认证或离线持钥证明核验申请者。不收私钥，不因来信含GUID就执行删除。
2. **validated / needs-information**：确认请求范围、先行取回状态、关联他人事实、保留政策及例外。需要保留的项目须逐项说明原因和期限，不任意默认永久保留。
3. **revoked-pending-deletion**：在既有授权事务中关闭选定的公开Consent/Proof/材料授权及必要认证；随后检查Profile、协作、建设者、Capsule等读取结果。此状态只表示访问已关闭。
4. **deleting**：按已批准的具体计划处理主库、认证/后台任务、派生缓存或索引；对他人事实采用最小关联墓碑或其他明确方案，不能擅自更改其贡献内容。
5. **partial / completed / declined-with-basis**：逐项给出主库、索引、日志、备份、外部副本的结果及剩余时间，附不含原始内容的证据引用。任何尚待过期的备份都必须留在partial中。

服务器不能擦除用户已下载的本机文件或第三方已保存副本。纠错按追加事实和更正说明处理，避免静默改写既有签名。新的删除API和执行器实现时应复用已有身份、Consent和审计，不另造身份协议。

备份删除必须关联restic保留周期和快照ID。灾备恢复先隔离；撤销旧授权之外，还要重放已确认的删除结果、检查各存储后才能重新服务。当前隔离恢复只完成旧授权关闭，尚没有删除重放账本。

## 部署和AI Agent操作顺序

1. 从现有配置发现准确端点、API/Worker进程、策略文件位置、备份和静态公告位置；不要从旧归档恢复凭据。参照[示例](../packages/galaxy-official/deploy/retirement.example.json)，填写实际运营者、原因、四个时刻及公开链接。
2. 把同一策略配置给API和Worker，更新既有configurationVersion并重启；检查公开JSON的策略ID/端点/时间与配置一致。不得以应用回滚为理由撤掉已公告的停服配置。
3. 在合成数据环境验证：正常→公告→取回→状态查询→关闭；取回完成、撤销生效、票据截止、新注册停止、老主体重绑定和数据未被预览删除。
4. 正式窗口前让用户拥有可用取回方式和联系渠道。逐项记录人工宿主体验、实际通知、真实取回、物理删除和长期托管的结果。

`retirement.test.mjs`含真实HTTP/客户端/SQL工作流；PostgreSQL的context工作流复用此演练。配置加载、边界时间和路由选择均有针对性检查。真实部署、运营通知、真实宿主、生产切换时的在途排空、删除执行与长期状态托管仍需各自证据。

关闭该实现的代码入口不能作为取消已公告停服的默认办法。若政策时间需更正，发布明确更正并保持API、Worker、官网和恢复环境一致；本批没有实施这些外部操作。
