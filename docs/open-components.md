# 开放组件、开源复用与当前交付

[项目首页](../README.md) · [愿景与架构](vision-and-architecture.md) · [Hub 与官方](ecosystem-and-hubs.md) · [资料使用范围](../RIGHTS.md)

银河希望通过可检查、可适配的组件，让不同客户端、专业能力提供者、社区和企业参与同一网络语义。开放的意义包括检查本机数据处理、连接已有系统、运行自己的专业能力及自主组织 Hub。

需要分别看四件事：软件是否开放及采用什么许可、某项官方服务是否免费、增值服务是否收费、参与者之间是否另有报酬。它们不是同一个开关。

## 当前已经公开什么

| 交付 | 当前范围 |
|---|---|
| [公开资料仓库 agigalaxy-public](https://github.com/agigalaxy-team/agigalaxy-public) | 项目、架构、生态和用户资料，图示、合成接口示例及公开资料合并工具；不是完整核心源码发行 |
| 官网 Native 0.1.16 开发版 | 有实际安装包、发行核验和打包代码；包内选定的 Galaxy 自有代码、Skill、集成辅助工具及随包文档按 **Apache-2.0** 提供 |
| 客户端第三方依赖 | 维持各自原许可；发行内保留锁定版本、许可清单和原始声明，不因银河的许可而统一改成 Apache |
| 全部服务与自建套件 | 核心服务实现仍另行管理，完整项目没有统一根许可和全套公开独立发行；不能把模块规划当成已可下载部署 |

当前客户端从[官网下载页](https://agigalaxy.org/downloads/)取得。许可范围以该发行的 `LICENSE`、`NOTICE`、第三方原文与版本为准；它不覆盖用户资料、私有历史、服务凭据或未发行服务组件。主代码仓库和公开资料的范围另见 [RIGHTS.md](../RIGHTS.md)。

本主代码仓库包含实现与开发历史，当前仍为私有仓库。源码入口另见主代码仓库的开发文档目录；能够访问源码不等于全部代码已按同一种开源许可授权。

## 原始设计中的开放模块

下表中的名称是原始设计的逻辑模块名，**不是已经全部独立发布的包名或仓库清单**。当前实现可能合并在客户端、业务服务和适配代码中。

| 原设计模块 | 为什么开放、供谁使用 | 当前公开交付与差额 |
|---|---|---|
| `galaxy-core-spec` | 共同主体、工作、来源、方法和撤回等语义，让其他实现能理解数据 | 公开资料仓库提供部分结构与技术说明；完整独立规范交付仍需整理 |
| `galaxy-sdk` | 为客户端和外部系统提供协议、结构与调用基础 | 已有客户端协议和集成基础；尚未形成通用独立公开 SDK 套件 |
| `galaxy-edge-core` | 在本机接入工作环境，便于检查哪些资料保留和外发 | 选定实现随 Native 开发版公开；宿主实际支持深度分别核对 |
| `galaxy-worker` | 让专业 Agent 或工具在授权环境提供能力，按配置与策略参与 | 有 Worker／A2A／Pack 接入基础；完整自建运行、长期供给和全天执行需独立验证 |
| `galaxy-hub-core` | 企业、社区和服务提供者自主经营本地网络 | 有 Hub、章程、成员和有限互联实现基础；完整独立开源部署交付尚未完成 |
| `galaxy-bridge` | 让外部平台按明确来源和映射参与，减少整体迁移要求 | 有外部来源与映射基础；不据此宣称任意平台均可直接接通 |
| `galaxy-conformance` | 检查版本、结构、签名、许可和撤回等兼容行为 | 发行含相应核验和协议报告；完整独立兼容检查交付需按实际版本提供 |

首批 Pack 沿版本清单和外部来源引用理解，安装使用原发布方或宿主机制。它不等于新建一个已经可用的二进制包市场，也不因为安装就获得监控、资料访问或自动成交权限。

普通客户端通过已有 AI 宿主的插件或 Skill＋MCP 使用相应功能，先在本机初始化 ID，官方账户按需要再接入。下表同时列出服务与运维基础，其部署由相应 Hub／官方维护者承担；普通客户端用户的准备事项另见[客户端入门](client-entry.md)。

## 复用成熟开源项目承担基础工作

银河需要开发自己的网络和业务语义，同时复用成熟基础。以下“已接入”指现有实现或工程接线，不表示每个工具在全部环境均已部署并验收。

| 工作 | 采用或选择的基础 | 银河负责的适配 | 当前情况 |
|---|---|---|---|
| 账户登录与管理认证 | [Keycloak](https://www.keycloak.org/) / OpenID Connect | 在线账户、本地身份、角色、关联及业务权限 | 现有认证基础；运营管理身份与业务身份分开处理 |
| 业务数据 | PostgreSQL | 网络对象、事务、版本、权限与当前状态 | 现有业务基础 |
| 产品界面 | React、TypeScript、Vite、Tailwind CSS | 网络功能、真实内容与完整使用过程 | 现有网站与产品界面基础 |
| 官网内容与运营后台 | [Payload](https://github.com/payloadcms/payload)、Next.js | 银河业务管理、独立管理认证、受控草稿与发布 | 已接入源码和候选，完整运营范围继续整合 |
| 持久任务 | [pg-boss](https://github.com/timgit/pg-boss) | 实际业务任务的权限、取消、重试、状态与结果接续 | 已进入工程接线；不以队列存在代替功能交付 |
| Hub／官方服务端聊天与归档 | [Prosody / XMPP](https://prosody.im/) | 服务器侧的房间、成员、消息许可与保留规则；向客户端提供银河 HTTPS 业务接口 | 客户端无需部署或配置 XMPP、无需单独 XMPP 账户；该实现不构成跨 Hub 通用资料联邦 |
| 文件与对象存储 | S3 兼容接口、ClamAV；[Garage](https://garagehq.deuxfleurs.fr/)作为自部署对象存储工程选择 | 上传、业务引用、可见性、扫描与生命周期 | 原有接口与扫描基础保留，自部署标准与运行覆盖继续落实 |
| 指标、告警与日志 | Prometheus、Alertmanager、Grafana OSS、Loki、Alloy | 业务关联、安全日志和统一维护入口 | 已选定的运行工具组合，真实集中采集覆盖需分别核对 |
| 统一备份与恢复 | [restic](https://restic.net/)、[pgBackRest](https://pgbackrest.org/) | 整站资料范围、恢复点对应、隔离恢复与实际结果 | 已采用的运行保障方案；部署配置和一次构建不等于完成灾备验收 |
| 用户 AI 与专用能力接入 | MCP、MCP Apps、Skill、A2A | 用户目的、真实授权、来源与业务动作 | 有接入基础，宿主界面和执行支持不同 |

外部组件保留各自许可和维护来源。这里说明采用关系，不替上游承诺银河的功能、稳定性或商业服务。

## AI 后台引擎仍是候选分析

更深入的 AI 运营后台，方向包括规则优先、AI 统筹、按策略自动处理和必要的人机协作。Agno／AgentOS、LangGraph.js 与 Deep Agents 及其组合仍在研究和逐项核对；候选稿、局部代码检查或原型不等于正式采用、全站上线或向普通用户提供官方模型。

这项建设复用现有业务能力和开源组件，具体模块、执行权限与界面继续按实际决定推进。用户端继续使用自己的 AI 宿主，运营后台引擎是不同范围。

## 继续参与

公开资料、反馈和纠错可从[贡献说明](../CONTRIBUTING.md)进入。涉及专业能力、Hub、Bridge 或其他系统合作时，应先说明具体目标、已有来源、实际支持版本、授权及所需交付，再讨论接入范围。

原始开放模块设计是方向，当前许可和可取得的发行物是实际交付依据。开放代码不公开用户资料，读取作品不自动授权改编、商用或训练；按内容自身的权利与许可处理。
