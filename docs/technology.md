# 技术栈与产品组成

[文档目录](README.md) · [网络功能](network.md) · [当前状态](status.md)

本页提供理解产品组成所需的技术概览，不包含核心实现、内部 API 契约、生产配置或完整部署方案。客户端发行的安装要求见[开始使用](getting-started.md)。

## 产品组成

| 部分 | 承担的工作 |
|---|---|
| 网站 | 主动发现、内容阅读与社区参与、聊天、项目及本人事项等网页入口 |
| Native 客户端 | 在已有 AI 宿主中连接银河，处理本地资料、身份控制及获准的网络操作 |
| 用户自己的 AI | 理解目的，结合实际取得的上下文解释相关性、整理帮助，并把结果接回原工作 |
| 业务服务与 Hub | 提供相应业务、权限与数据服务，为自行组织网络保留基础 |
| 外部接入 | 通过支持的协议和接口接入 Agent、工具或外部系统；实际能力取决于配置与授权 |

## 采用的主要技术

| 领域 | 技术 | 用途 |
|---|---|---|
| Web | TypeScript、React、Vite、Tailwind CSS | 类型化开发、组件界面、构建与样式 |
| 服务 | Node.js | 业务服务与相应客户端运行 |
| 数据 | PostgreSQL | 业务数据及相关持久化 |
| AI 宿主接入 | MCP、MCP Apps、Skill | 工具连接、支持环境中的交互界面及使用指引 |
| Agent 执行接入 | A2A | 所支持 Agent 之间的执行协作接口 |
| 认证 | Keycloak / OpenID Connect | 所配置网站环境的账户认证 |
| 通信 | Prosody / XMPP | 相应即时通信服务 |
| 文件 | S3 兼容存储、ClamAV | 对象存储及配置的文件安全扫描 |

表中技术来自当前实现采用的依赖与组件，各项不一定在每种入口中同时运行。安装客户端也不要求用户先部署完整网站配套服务。公开客户端 0.1.16 要求 Node.js 22.13+，其他组成部分的运行版本独立管理。

## 接入与开放方向

银河保留 Hub、Bridge、MCP 和 A2A 等接入基础。协议存在、某项接入已经实现和完整独立生态成熟是不同阶段，跨环境行为需要实际验证。

当前 Hub 有 `galaxy-direct-proof/1` 的两方有限范围直接互联实现，通过 HTTPS、选定公钥、协议与来源授权检查交换选定证明或非叙述贡献字段。Prosody / XMPP 承担相应聊天室通信与存储接入；采用 XMPP 本身不证明跨站聊天室联邦已经成立。身份、签名、来源、撤回与交换边界见[技术核对说明](technical-faq.md)。

更完整的五层职责见[愿景与架构](vision-and-architecture.md)。官方公共入口、参考 Hub、第三方 Hub 与可选 Relay 的职责及信息流见[Hub 与官方的运作](ecosystem-and-hubs.md)。

## 基础组件的工程整合

运营后台已经采用 Payload、Next.js 与银河业务扩展的工程组合，pg-boss 提供持久任务基础；存储、监测、日志和统一备份恢复继续复用成熟工具。现有源码接线、候选、实际部署与完整功能验收分别处理，不把依赖存在写成全站能力完成。

组件列表、当前整合范围、原始开放模块与实际许可见[开放组件与开源复用](open-components.md)。Agno／AgentOS、LangGraph.js 与 Deep Agents 等后台引擎仍是研究候选，不能混入已采用技术栈。

公开资料不把正在评估的框架列为已采用能力，也不以框架选型代替产品效果。更深层的发现、协作和自建网络能力以[当前状态](status.md)及后续实际发行资料为准。
