# 账户与 ID 的公开查询

账户持有者在“账户资料”的公开资料设置中开启查询，并分别选择是否展示关联 ID、是否展示本人外部凭据。两项新增展示选择默认关闭；原有“账户资料 / 账户资料和公开帖子”选择继续生效。账户和 ID 保留各自的主体类型、历史及权限。

每个在线账户都有固定 UID，当前格式为12位大写字母、数字混合编码，符合6–16位范围。UID 由程序分配并由数据库保证唯一；它与内部账户 UUID、本地银河 ID 和登录凭据分别使用。新账户的初始用户名等于 UID，之后可修改用户名，UID保持不变；已有自选名称保留。本人 session、资料设置与获准的公开资料返回同一 UID。

官网全站搜索支持准确的 UID、银河 ID 或账户 UUID。ID 个人资料中的“关联的开放账户”可进入账户公开页；账户页按持有者选择列出当前关联 ID、外部凭据及公开帖子。工作资料、完整会话和未上传的本地材料保持原有私有范围。

## HTTP

以下接口均为匿名只读 GET，响应使用 `Cache-Control: no-store`。列表支持 `after` 和 `limit`，默认20、最高50；按响应中的 `nextAfter` 继续，直到其为 null。

| 路径 | 内容与游标 |
|---|---|
| `/v1/account/public/:accountId` | 账户公开名、主体类型声明、展示选择和按范围附带的公开帖子 |
| `/v1/account/public/by-uid/:uid` | 按精确 UID 查同一份公开资料，包含真实账户 UUID；不开放模糊或邮箱查询 |
| `/v1/account/public/:accountId/ids` | 当前关联的 ID；`after` 为上一页末项的 `subjectId` |
| `/v1/account/public/:accountId/credentials` | 本人外部凭据的来源及当前状态；`after` 为凭据 UUID |
| `/v1/account/public/by-id/:subjectId` | 允许展示此 ID 关联的账户；`after` 为账户 UUID |

账户关闭查询时，其公开入口返回404。关闭某项展示时，相应列表返回404，按 ID 反查也移除未开放该关联的账户。不存在的 ID 与没有开放关联的 ID 均返回空账户列表。关联查询重新检查当前服务、配置的账户来源及未撤销关系；关联存在不授予调用者账户控制或其他主体的私有资料。

本人设置仍通过带有效账户 session、账户 ID 和 CSRF 的 `/v1/account/settings` 读写。`publicQuery.showLinkedIds`、`publicQuery.showExternalCredentials` 是可选 boolean；旧客户端省略字段保存时保留当前值。`expectedRevision` 保持原有并发更改检查。更改会话清理期限或客户端上传档位不改变公开查询选择。

外部凭据公开投影只包含与当前账户归属相符、未停止展示的记录：出具者、对象、适用范围、日期、来源、签名与撤销状态。JWT 原件及发行者私有声明保持私有。过期、撤销、撤销未知或发行者尚未配置分别按实际状态呈现；银河不生成认证结论、能力预估或可信度总分。凭据导入及发行者配置见[外部凭据](external-credentials.md)。

## AI Agent 部署

先从目标环境的现有配置发现 endpoint、账户入口和发行者文件引用，沿原凭据保存方式注入进程。迁移90增加默认 false 的关联和外部凭据展示字段；迁移92为所有现有线上账户补齐唯一 UID，并为没有名称的资料保存初始用户名，已有非空名称、关联、凭据和上传档位保持原值。API、Worker 与迁移角色使用同一捕获发行目录；按现有服务发行流程先迁移再切换 Web。迁移92之后继续使用支持新约束的 API，不将旧 schema91 服务回退到已升级数据库，也不通过 SQL 撤销 UID。

新账户创建时通过数据库唯一约束与有界碰撞重试分配 UID；同一已验证发行者和主体的重试返回原账户，不重复生成身份。资料保存不接受 UID 字段，数据库拒绝更改已分配 UID。按 UID 查询继续执行账户的公开设置，关闭查询的账户与不存在的 UID 均返回404。

部署后读取 `/readyz` 确认所选发行可用。使用隔离资料确认旧账户只开放 profile 时不出现新增关系或凭据，再明确开启展示，沿 ID、账户、ID 完成查询；关闭展示或撤销关联后重读应移除相应数据。生产核验可匿名读取状态与不存在对象的查询，不需要为此创建生产测试账户或发布合成材料。

调用者应在可见性恢复、重新聚焦及翻页时读取当前范围；读取失败或离线时收起旧结果，避免把先前获准的展示当成永久公开副本。公开元数据中的签名、日期、来源状态各自表达具体检查结果。外部发行者未配置时保持明确的未配置状态，不填入示例发行者或虚构资格。
