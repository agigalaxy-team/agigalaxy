# 原生项目发现与接触意愿 v1

2026-09-11。首版服务现已接到现有 OpenCode Adapter、便携客户端和本机签名运行层。使用已有会话与资料发布流程；无需新增账户、数据库或聊天平台。

操作入口：`/galaxy → 接入银河 → 分类型搜索 → 项目／模块机会`。当前会话需要 history；编辑资料另需 consent，调整意愿需要 notifications。未连接时沿用现有连接入口，不会自动绑定。顶层六项、初始化、0返回及Esc退出规则没有修改。

## 现在可以操作的路径

1. 进入“我的资料与项目介绍 → 编辑自述 → 项目／模块介绍”，添加或编辑名称、简介、功能标签、技术标签、来源网址、项目／模块类型和发现候选开关。移除也只改变当前草稿。
2. 完成编辑后返回自述页面，选择“预览发布”，核对完整内容、可见性与准确确认文本。保持原本机签名和Consent机制，不会把添加草稿当作已经发布。完整正文超过12000字符时先要求精简，不先写入Consent。
3. 打开“接触意愿”并明确开启发现，可设置长期目的和功能关注。选择自己的已发布项目即可查询机会；自己的私有介绍也可主动查询，候选来源必须满足当前可见授权。
4. 卡片显示共同功能、共同目的、双方不同的功能与技术。摘要缩略，完整介绍与差异可展开；来源资料会重新读取当前版本，撤销或私有替换不会显示旧公开资料。来源网址只是引用，不自动打开浏览器或抓取内容。
5. 临时意愿可切换欢迎／暂停、输入小时数并选择短期目的或关注方向。保存后作用于下一次查询，到期恢复长期设置；也可随时清除。小时数由使用者输入，没有设定默认业务期限。此设置尚未接入未来的机会推送或聊天室通知。

普通交流可以是唯一目的，不要求模块复用、报酬或形成任务。`discoverable:false` 只是排除候选，不能隐藏已经公开发布的Profile内容；资料的可见性仍由发布Consent决定。项目介绍与自报能力始终显示为自述，不能转换成已验证能力。

项目与卡片列表每页展示最多6项，保留1–9数字入口。编辑项目时完整字段仍保留于草稿，菜单里的缩略显示不会截断提交内容。所有偏好修改复用主体revision；冲突或取消后的结果需要重新读取，不自动覆盖或重发。

## 客户端和安装产物

新增 `@galaxy/client/project-discovery`，导出 `createProjectDiscoveryClient`、`projectDescriptionSchema` 和 `discoveryPreferencesSchema`。实例提供 query、preferences、save，复用既有 sessions；输出检查自述标记、来源引用和分页上限。原 `@galaxy/client/discovery` 继续用于服务Manifest发现，没有改名。

原生本地候选位于 `outputs/native-host-20260911-discovery-1/`，包含115个源文件构建的9个ESM。包版本仍为开发中的0.1.0，候选目录独立，不覆盖以前已公开的同版本包。实际安装回执见[installation.json](../outputs/native-host-20260911-discovery-1/installation.json)。本批未修改全局OpenCode配置，没有把该候选发布到官网或npm；当前公开旧包不含本次发现界面。
