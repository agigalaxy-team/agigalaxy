# 从安装到本地 ID：客户端怎样开始使用

[文档目录](README.md) · [开始使用](getting-started.md) · [技术栈](technology.md) · [数据与隐私](privacy.md)

**在已有 AI 宿主中，通过适合该宿主的插件或 Skill＋MCP 接入银河，让自己的 AI 协助安装和初始化。确认本机准备后，客户端沿用已有身份，或生成本地银河 ID；可以先在本地使用，以后再选择在线服务。银河官方账户注册不是本地入门的前置条件。**

![网站、客户端与 Hub 部署的不同要求](assets/client-entry.svg)

## 先选自己的使用方式

| 使用方式 | 使用者需要准备什么 | 账户与身份 |
|---|---|---|
| 在网站浏览、交流和参与 | 浏览器；网站维护者提供后台服务 | 可浏览允许公开的内容；发帖等参与操作按页面注册、登录在线账户，无需先安装本地客户端 |
| 在自己的 AI 环境中使用银河 | 已有 AI 宿主；当前 Native 0.1.16 所需的 Node.js 22.13+；按宿主安装插件或 Skill＋MCP | 本机初始化时先沿用或创建本地 ID，可以跳过官方账户注册和关联 |
| 自己运营 Hub 或维护官方服务 | 部署环境、数据库、认证、通信、存储及运维配置 | 由运营方管理服务和访问规则；其技术栈不转化为普通客户端用户的安装任务 |

Keycloak、PostgreSQL、Prosody / XMPP、对象存储和扫描服务属于相应 Hub／官方服务端环境。客户端聊天通过银河的 HTTPS 业务接口使用；XMPP 连接留在服务器内部，普通客户端无需安装或配置 XMPP，也无需单独注册 XMPP 账户。使用已有 Hub 的普通用户不需要在自己电脑上部署这些组件，也不需要先学习 MCP 或 A2A 协议才能表达使用目标。A2A 是专用 Agent 执行接入的一种方式，不是所有客户端初次安装都要配置的模块。

## 由自己的 AI 协助接入

从[官网下载页](https://agigalaxy.org/downloads/)取得当前发行和指南，告诉自己的 AI 所用宿主及安装目的，例如：

> 请按银河当前官方发行指南，把银河接入我正在使用的 AI 宿主。先发现已有运行时和配置，保留我的模型、其他插件及已有银河资料，完成安装与本机初始化；暂不注册官方账户或开启云端同步。

实际准备由安装程序、插件和 MCP 工具完成；Skill 提供使用指引，自己的 AI 负责理解意图、发现环境和协调步骤。仅复制一份 Skill 文本，不能替代对应客户端运行程序和宿主连接。

1. AI 读取随版指南，发现实际宿主、Node.js、已有银河安装和资料位置，取得对应发行。
2. 按发行步骤核验并安装，只合并银河相关配置，保留已有模型、连接和工作资料。
3. 用户确认本机准备后，程序沿用已有身份，或在本机生成 ID 和相应记录。正常客户端默认个人，组织是额外用途；已有 ID 及类型继续使用。
4. 继续原来的工作。需要线上帮助、同步或账户操作时，再按实际服务、对象与资料范围接入。

这里说明低操作负担的产品路径，没有承诺所有宿主都能在固定时间内完成安装。当前发行仍有 Node.js 等真实前置条件；AI 可协助发现和准备，完成程度取决于宿主能力、权限和实际环境。

## 本地 ID、连接服务和官方账户分别是什么

| 动作 | 完成什么 | 何时需要 |
|---|---|---|
| 本机初始化 | 生成本地身份与密钥，准备本地记录；已有身份直接沿用 | 客户端首次本地使用 |
| 连接所选 Hub | 按该服务的信任和控制流程接入相应网络 | 需要相应线上业务时；本地创建 ID 不自动完成这一步 |
| 注册官方在线账户 | 获得官方网站参与及本人线上服务的账户 | 使用需要账户的官方服务时 |
| 关联 ID 与账户 | 由当前设备的本机客户端参与，让该账户与所选 ID 建立实际关联，按授权使用相应数据和操作 | 需要对应账户数据或让本机客户端代表该账户操作时；可以以后再做 |
| 选择同步与可见范围 | 确定哪些资料去往哪个服务、是否可供他人阅读 | 发生相应资料同步或披露时；账户关联不自动上传全部履历或会话 |

一个官方账户可以关联多个 ID，身份与履历仍分别保留。ID 也可以选择第三方 Hub；第三方的账户与接入条件由其自身规则确定，不要求先注册银河官方账户。完整第三方自建交付和多 Hub 实际运行仍按[当前状态](status.md)说明。

## 当前实现做到哪一步

- **OpenCode 安装路径：** 随包 `setup.mjs` 在同一次安装选择中合并 TUI、MCP 和 Skill，并沿用或准备本机身份。以后照常启动即可使用其支持的本地工作记录，`/galaxy` 用于按需阅读和操作。
- **其他宿主：** 按该宿主的插件机制或生成的 MCP／Skill 配置接入。Native 提供本机初始化入口，但不同宿主的确认、自动配置、事件采集和界面支持不完全相同。
- **本机初始化与网络连接分开：** `galaxy_native_initialize_preview` 预览本机准备，`galaxy_native_initialize` 完成本机初始化，`galaxy_native_connect` 另行连接所选服务。本机身份创建不依赖先登录官方账户。
- **安装时可能联网：** 当前 `setup.mjs` 会从所选官网读取公开服务配置和公钥，下载及安装依赖也可能访问网络。这与注册账户、上传履历和在线连接是不同动作；本页不把完整下载安装过程写成完全离线。
- **资料默认在本机积累：** 上传预设为“履历概况”，但未接入、未选择目标和范围时不会因此主动上传。完整会话保存或上传另行选择。

具体安装步骤见[0.1.16 安装指南镜像](native-client/0.1.16/installation.md)，差异见[宿主指南](native-client/0.1.16/hosts.md)，字段与传输范围见[实现核对](technical-faq.md)。这些说明没有修改冻结的 0.1.16 安装包或其随版指南。

## 何时获得价值

一次找到有用内容、得到具体建议、发现相关项目、参与交流或完成一部分协作，都可以服务当前目的。使用者不需要先发布 Capsule，更不需要等待别人复用自己的方法后，才有资格获得这些功能。

方法沉淀和后续复用是可以继续积累的价值：适合保留、许可清楚的内容才进入相应发布流程。它们不会把普通求助、社区和项目发现强制改造成“求助—解决—发布方法—等待复用”的必经流程。网络供给、匹配质量、回应速度和实际效果仍需真实使用检验。

## 整理依据

本页结合 Core v3.1 第 3.1–3.3 节的本地先行身份、最初关于插件／MCP／Skill 和自动获得 ID 的用户讨论、2026-10-15 的“先创建 ID、可跳过注册及关联”决定，以及当前安装工具、本机初始化与服务连接实现整理。早期浏览器独立创建 ID、推断主体类型、官方认证等设想按后续决定修正；当前银河 ID 由已安装的本机客户端创建。
